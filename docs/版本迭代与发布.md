# 版本迭代与 GitHub 发布

## 仓库与安装包

- Git 仓库保存源码、测试、文档与构建脚本。
- GitHub Releases 保存带版本号的 ZIP 安装包和 SHA-256 校验文件。
- dist 不提交到 Git；GitHub 自动提供的 Source code ZIP 不等于安装包。
- 当前主分支为 master，仓库为私有。公开可见性和开源许可证分别决定，公开前由作者选择许可证。

## 日常开发

```powershell
git switch master
git pull --ff-only
git switch -c codex/your-feature
# 修改代码与相关测试
python tests/run_tests.py
python tools/build_release.py --check
git add <本次相关文件>
git commit -m "feat: describe your change"
git push -u origin codex/your-feature
gh pr create --base master
```

CI 在 master 提交和 Pull Request 时运行离线测试并构建 ZIP。
Actions 的测试构建可下载用于验证，不代表正式发布。
GitHub 托管运行器没有 ADS，CI 不验证真实 ADS 建图和仿真。

## 发布下一版（以 1.0.2 为例）

1. 在功能分支中修改 backend/paths.py 的 PLUGIN_VERSION 为 1.0.2。
2. 更新 CHANGELOG.md，新增 docs/releases/1.0.2.md，写清功能、修复、验收与限制。
3. 执行离线测试和构建；在已授权 ADS 2027 上验证本次受影响功能。
4. 将改动通过 Pull Request 合入 master，等待 CI 通过。
5. 在该提交创建并推送标签：

```powershell
git switch master
git pull --ff-only
git tag -a v1.0.2 -m "ADS Agent 1.0.2"
git push origin v1.0.2
```

标签必须与 PLUGIN_VERSION 一致。发布流程自动测试、构建并创建草稿 Release，附带 ZIP 和 SHA256SUMS.txt。
进入 GitHub → Releases，检查草稿的说明和附件，完成实机验收后点 Publish release。
若 Actions 未通过，不会完成安装包发布；先查看失败步骤再修复。
已发布标签不要移动；修复发布问题请递增版本创建新标签。

## 安装升级与检查更新

用户从 Releases 下载新版本 ZIP，关闭 ADS，解压并运行安装入口，再启动 ADS。
配置和会话默认保留在 %LOCALAPPDATA%\ADSAgent，重要数据建议先备份。
当前建立的是工程构建与发布流程；插件内自动检查更新和自动下载安装尚未实现。
私有仓库附件仅对有读取权限的账户开放，不应把 GitHub 访问令牌写进插件。

## 校验下载

```powershell
Get-FileHash .\ADSAgent-1.0.2.zip -Algorithm SHA256
```

与同一 Release 附件 SHA256SUMS.txt 的完整哈希核对。

## 回退

旧版程序可从对应 Release 下载。程序回退不保证较新的用户数据格式向后兼容；
DATA_VERSION 变化时按版本说明执行迁移或恢复备份。
