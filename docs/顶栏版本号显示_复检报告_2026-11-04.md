## 3. 与契约的冲突、歧义，以及我实际观察到的实现细节

### 3.1 契约 §6.4 "跑完应 +1 文件" 与 run_tests 过滤语义不符（措辞问题，非实现缺陷）

`tests/run_tests.py:135`：`cases = [c for c in CASES if not (stdlib_only and c[3])]`。我的文件登记于 `:122`，第 4 字段 `needs_pyside=True`，所以 `--stdlib` 不执行它，总数仍是 68。结论：`--stdlib` 的"无新增失败"仍成立（67/1/68 与基线逐项一致）；但"应 +1 文件"不成立。**建议 lead 在验收记录中写明"stdlib 层文件数不变；qt 全量（不带 `--stdlib`）才 +1"**。我没有改 `run_tests.py`（C 所有）。

### 3.2 已修复的实现缺陷：prepare 复检为 up_to_date 时按钮卡死（本波最重要的发现）

- 发现（级别 D，动态探针，修复前快照）：A 首次落地（mtime 00:41:40）的 `_on_update_prepared` 中 `elif status == "up_to_date"` 分支只调 `_update_state(...)`，不复位按钮。实测：喂 available → 点击 → 喂 `{"status":"up_to_date","current_version":"1.4.0",...}` 后，按钮 `text='正在下载更新…'`、`enabled=False`、tooltip 仍是下载中、`_update_top_state` 仍 `'available'`，再点击无反应（禁用态被 `_on_top_update_clicked` 直接 return），只能重启面板。
- 可达性（后端依据，非假想分支）：`backend/update_service.py:346 _prepare_locked()` 在 `:350` 每次重新 `_check()`；`:351-352` "status != update_available 就直接 return"，而 `_check()` 可返回 up_to_date（`:142`）。即"用户看到一键更新、点下去、后端复检说其实已最新"是真实可达的。
- 契约冲突：违反 §2 up_to_date 行"可见、可点、文案 v{current}"，且禁用只应属于 preparing 行。
- 处理：已按 5 点回报 lead；lead 裁决"修"（并明确禁止用 `_restore_top_update_btn()`，因其 tooltip 是"上次更新失败"措辞）。A 于 00:46:33 落地修复（panel.py 现 7097 行），`_on_update_prepared` 的 up_to_date 分支（现 `:2913-2924`）补了：清 `_update_apply_requested`/`_update_latest_available`、置 `_update_top_state="up_to_date"`、`if current: _update_current_version=current`、`_update_state(...)`、`_show_top_update("")`、`setEnabled(True)`。
- 复验：我据此新增第 12 条用例，00:47:01 实测 **PASS 12/12**；修复前同断言必红（已由探针记录实际值）。
- 附带发现并确认**已覆盖**：`_prepare_update` 启动失败路径（panel.py:2864-2871）也调用了 `_restore_top_update_btn()`，不会卡在"正在下载更新…"。

### 3.3 措辞类歧义（均按"通过"处理，不改断言）

1. **checking**：契约写"tooltip 同上 + 正在检查"；实现为 `当前版本 v1.3.5，正在检查更新…（不会下载任何文件）。`（`_show_top_update`，panel.py:2672 起）。实测（级别 D）：文案保持 `v1.3.5` 不变、可点、tooltip 含"正在检查"——符合"文案不变 + 补正在检查"的意图。
2. **error/离线**：契约要求 tooltip 含"检查更新失败"+原因摘要（可截断）；实现为 `当前版本 v1.3.5，上次检查更新失败：{reason[:60]}。点击可重试。`——含子串"检查更新失败"、原因截断 60 字符，符合。
3. **prepare 失败复位** tooltip 双重措辞：`当前版本 v1.3.5，上次检查更新失败：上次更新失败，未改动安装。点击可重试。`（`_note_top_update_error("上次更新失败，未改动安装")` 与 error tooltip 前缀叠加）。语义正确但啰嗦；A 本波未改，按 lead 指示不要求返工，记为"仍啰嗦但语义正确"。
4. **applied** tooltip：`已更新到 v1.4.0，正在自动重启后端…`——含"已更新到 v{...}"，符合。

### 3.4 其他实际观察

- 版本来源严格符合 §3：`_local_plugin_version()` 惰性 import `pathbridge` + `getattr(...,"PLUGIN_VERSION","")` + `except BaseException`；无 hardcode `1.3.5`；`_top_btn_current_version()` 数据 `current_version` 优先、空才本地；`_v_label()` 去 `v` 前缀避免 `vv1.4.0`。

- 两个面板实例的状态全部挂在实例属性上（`_update_latest_available`/`_update_top_state`/`_update_current_version` 均在 `__init__` 初始化），实测互不串（第 11 条）。
