# 原厂模型压缩包管理 —— 实现与验收记录（2026-10-08）

本轮目标：让用户能在聊天面板上传原厂模型 ZIP（村田 / TDK / Infineon 等），
在指定 ADS Workspace 中按需导入、查询真实模型、参与建图仿真与优化闭环。

**结论先说**：离线实现与自动化测试全部通过；**ADS 2027 实机端到端验证本轮
未执行**（原因与待验证清单见文末「未验证项」，不宣称已完成）。

## 二、分层实现

```
附件（📎 按钮 / 拖入 ZIP）
  │  POST /models/upload  —— 独立二进制通道（非 Base64/非 JSON）
  ▼
backend/model_store.py    资产层：保存/去重/哈希、清单原子写+跨进程锁、
  │                       安全解压、包识别、型号索引、状态机
  ▼
backend/model_tools.py    编排层：工作区绑定、导入流水线（scan→extract→
  │                       index→attach）、验证回写 ready
  ├── list/inspect        本地读清单，不必叫起 ADS
  └── import/validate     派发到 ADS 端
  ▼
addon/ads_agent/model_ops.py   ADS 端：Design Kit 挂接、只读库浏览、
                               model_def 参数读取、验证门禁
```

沿用既有机制，未另建第二套：无新工具服务（走现有 toolserver DISPATCH）、
无新仿真系统（复用 `run_simulation`）、无新项目存储（聊天项目只存附件引用）。

## 五、本轮修掉的真实缺陷（非"看起来不对"，是测试或实跑暴露的）

1. **相对路径基准错**：`archive_relpath` 原写成相对 `store_root`，规格要求相对
   **工作区**，导致编排层每一步都取到不存在的路径（全部 extract/index 失败）。
2. **状态机挡住合法路径**：`saved → pending_import` 被拒，正常导入流程走不通；
   同时保留「未经导入验证不得进 ready」这条硬约束。
3. **`library_attach` 被整体覆盖**：挂接时用 `update_package` 覆盖，冲掉了扫描阶段
   解析好的 `kit_root_candidates` / `defined_libraries` → 界面看不到套件根候选、
   `vendor_filter` 永远筛不出库。改为**合并写入**（`_attach_update`）。
4. **`reused` 标志丢失**：`scan_archive` 返回重新读出的记录，一次性标记不在清单里，
   界面分不清「新上传」与「复用已有资产」。上传响应改为先取标记再扫描。
5. **404 挂连接**：包不存在时异常穿透 handler，响应没发出，客户端看到
   `RemoteDisconnected`（像服务器崩了）。改为取包用容错的 `_lookup` + 兜底 500。
6. **`file_relpath` 字段名不存在**：索引里叫 `relpath`，取值恒为空。
7. **指纹命名撞车**：`model_fingerprint` 同时被用作「元件定义指纹」（字符串）与
   「模型文件内容指纹」（dict），跨模块必然读错。拆成
   `component_def_fingerprint` 与 `model_fingerprint`。
8. **可重入锁被破坏**（我自己引入又修掉）：一度把 `acquire` 的可重入分支删掉，
   `_mutate → save_manifest` 二次加锁变成抢自己已持有的锁 → 上传接口永久挂死。
   已恢复并写明必要性。
9. **型号提取对常见命名漏判**（接 `get_vendor_model_info` 索引时暴露）：
   - `GRM155_R1.s2p` → `part=None`（`R1` 封装变体标号未被识别）
   - `GSL802AD_20mA_ADS_compatible` → `part=None`，**用户样本里的真实偏置也没提取到**
   根因：`_BIAS_RE` 要求"关键字 + 数值 + 单位"（`VCE_2.0V`），匹配不到
   "单位在前、无关键字"的裸写法（`20mA`）。补 `_BIAS_LEADING_RE` + `_DESC_SUFFIX_RE`
   + `_KNOWN_SUFFIX_RE`。
   **两次踩坑都记在注释里**：① 泛化后缀正则会把 `BFR106` 切成 `BF`、`GRM155` 切成
   `GRM`（型号被改短比查不到更危险）；② `(?i)` 下 `\b` 在 `20mA_ADS` 的 `A|_`
   之间**不存在**（`_` 属 `\w`），加 `\b` 直接让整条正则失配。
   修正后：`GSL802AD_20mA_ADS_compatible → (GSL802AD, {ID: 20 mA})`、
   `GRM155_R1 → GRM155`、`BFP181_VCE_2.0V_IC_10mA → (BFP181, {VCE:2V, IC:10mA})`、
   `BFR106/GRM155/C1000X7R → 原样保留`。

10. **工具描述承诺的字段没有消费方**（ads-attach 独立发现）：`get_vendor_model_info`
    描述里写了"频率范围与参考阻抗"，但 ADS 端 `model_def` 拿不到（已核对本版本
    `ModelParam` **没有 min/max 字段**）。归属决定给**后端** `model_tools.py` ——
    索引数据在 `model_store`，让 ADS 侧做只能靠传参徒增接口复杂度。
    现已接上：返回体新增 `model_index`，含 ports/freq/Z0 及其**溯源字段**
    （`reference_impedance_source: option_line`）。取不到时 `available: False`
    + 说明原因（手工挂接的原厂库不在索引里），**不拿别的元件的数据凑**。
    覆盖目标频段时给 `frequency_coverage_note` 提示不外推。
    型号按 `normalize_part` 归一化匹配（**不做模糊匹配** —— `BFP181` 与
    `BFP181W` 是两个型号），并把 `_normalize_part` 提为公开 `normalize_part`，
    避免规则分叉。

    后续接入 `model_store.find_models()`（数据产出方提供检索），把返回体升级为
    **`model_index.hits` 列表** —— 同一型号有多个偏置变体（实测 BFP181 有 276 个
    .s2p 变体），给单条等于让调用方随便挑一个偏置。顶层字段是"第一条"的概览，
    notes 里明确指向 hits 让调用方按偏置条件选。

### 索引上限 2000 → 10000（并纠正一个误判）
`find_models` 实测 Infineon 包 8184 条时只索引 2000，疑似导致型号查不到。
**先查证再改**：直接扫 ZIP 发现该包里**根本不存在 BFP181W / BFP940 的模型文件**
（BFP181 系列 306 个 .s2p，无 W 后缀版本）—— `found=False` 是正确结果，
不是截断问题。上限该提（避免真实型号落在未索引区），但不能靠它解决
"本就不存在的型号"。

提到 10000 后实测：8184 条全部索引，单包耗时 34s，manifest 6.17 MB（可接受）。
超出再考虑把 `models` 拆成按包的独立文件（首版不做，避免过度设计）。

### 命中排序：模型数据文件优先于元件库文件（真实样本暴露）
Infineon 包里 BFP181 同时有 120 个 `.ael` 和 306 个 `.s2p`，索引顺序上
`.ael` 可能先被命中 —— 不排序的话调用方拿"第一条"当概览会得到**一堆 null**，
看起来像"这个型号没有频率数据"，而其实有（10MHz–6GHz / Z0 50Ω / MA 格式）。
`find_models` 现在按"有模型数据优先"排序。修正后实测：
```
BFP181 hits[0] = BFP181_VCE_0.50V_IC_1.0mA.s2p
                 bias={VCE:0.5V, IC:1mA} ports=2
                 freq=10MHz~6GHz Z0=50Ω fmt=MA   ← 与文件头 # GHz S MA R 50 一致
```

> 另：我曾误判「锁文件只互斥跨进程」，据此给 `ManifestLock` 加了进程内 mutex。
> 实测证伪（B 在 A 持锁时阻塞 0.35s 而非立即返回），已撤回该改动并在 docstring
> 里记下这条实测结论 —— 错的方向性注释比没有注释更贵。
> 同类错误还有这次：把"型号查不到"归因成索引截断，实际是包里没有该型号文件。
> **两次都是"先下结论再找证据"，共同教训是：归因必须先验证。**
