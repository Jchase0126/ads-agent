## 1 工具接口（ads_ops.DISPATCH + backend/tools.py TOOLS 同名同参）

### 1.1 `list_workspaces`（新增）

入参：
- `query`: string，可选。按名称/路径片段过滤，大小写不敏感。
- `max`: integer，可选，默认 20，上限 100。
- `roots`: string 数组，可选。额外扫描根目录，通常省略。

返回（不抛异常，除 ADS 端整体不可用）：
```
{
  "workspaces": [{"name", "path", "valid": bool, "last_used": "ISO8601|", "source": "recent|scan"}],
  "recent": [{"name", "path", "last_used"}],
  "roots": ["实际扫描的根目录"],
  "scanned": int,          # 实际检查过的目录数
  "truncated": bool,       # 是否因上限提前停止
  "notes": ["跳过/降级原因"]
}
```
扫描纪律（硬要求）：只扫已知根目录的 1–2 层子目录；单根目录条目 >2000 直接跳过并写 note；
总根目录数 ≤10；整体耗时预算 ≤3s（超预算即停止并 `truncated=true`）；**禁止 `os.walk` 全盘/盘符根**。

### 1.2 `create_workspace`（新增）

入参（name 与 path 至少给一个；都给时以 path 为准）：
- `name`: string，工作区名（目录名）。
- `root`: string，父目录；省略时按 1.4 解析。
- `path`: string，完整目标路径。
- `library`: string，可选，创建后新建的首个可写库名。
- `open`: boolean，默认 true，创建后是否立即打开。
- `force`: boolean，默认 false。当前已有**其它**工作区打开时必须为 true 才切换。

返回：
```
成功：{"created": true, "name", "path", "workspace_open": bool, "libraries": [...],
       "writable_libraries": [...], "library_created": "名|", "previous_workspace": "路径|",
       "force_closed": bool, "notes": [...]}
拒绝：{"created": false, "reason": "exists"|"needs_force"|"invalid_name"|"invalid_path"|"sdk_unsupported",
       "path": ..., "current_workspace": ..., "message": "给用户看的中文说明", "candidates"?: [...]}
```
纪律：目标已存在 → `exists`，**绝不覆盖/删除**；名称非法（空、`.`/`..`、含 `\/:*?"<>|`、超 120 字符）
→ `invalid_name`；已有其它工作区打开且 `force=false` → `needs_force`（附当前工作区路径）；
`de.create_workspace` 不可用 → `sdk_unsupported`。创建成功但打开失败要如实返回
`created=true, workspace_open=false` 并带 note，不得报成"已打开"。

### 1.3 `open_workspace`（增强，保持向后兼容）

新增/扩展入参：`force`: boolean，默认 false。
`path` 语义扩展：可以是①完整工作区目录；②以路径分隔符结尾的父目录（在其 1 层子目录中找）；
③名称或名称片段（在 recent + 已知根目录里解析）。

返回（成功沿用原字段并新增）：
```
{"workspace_open": true, "path", "libraries", "writable_libraries",
 "already_open": bool, "opened": true, "switched": bool, "notes": [...]}
```
需用户决策时**不抛异常**，返回：
```
{"opened": false, "reason": "ambiguous"|"not_found"|"needs_force"|"invalid_path",
 "candidates": [{"name","path","last_used"}], "current_workspace": "...",
 "message": "中文说明"}
```
- 片段命中 ≥2 个 → `ambiguous`（禁止自行挑一个）。
- 片段命中 0 个 → `not_found`，附 `candidates`（空）与 `message`（提示可用 list_workspaces 或给完整路径）。
- 当前已打开**不同**工作区且 `force=false` → `needs_force`。
- 完整 path 存在但缺 `lib.defs` → `invalid_path`（沿用现有中文口径）。
- 只有 SDK 缺少 `open_workspace` 才抛 `RuntimeError`（保持现有行为）。

### 1.4 根目录 / 最近记录解析（唯一真源）

- 最近记录：`<数据根>/recent_workspaces.json`，`{"version":1,"items":[{"path","name","last_used"}]}`，
  最多 20 条，最近使用在前；原子写（临时文件 + `os.replace`）。**同时继续写 `last_workspace.txt`**
  （旧入口与既有测试依赖它，不得破坏）。
- 数据根：沿用 `_last_workspace_file()` 已有的 pathbridge/`ADS_AGENT_DATA_DIR` 解析方式。
- 新建根目录解析顺序：`root` 参数 → 环境变量 `ADS_AGENT_WORKSPACE_ROOT` → 最近工作区的父目录 →
  `<数据根>/workspaces`。
- 发现根目录解析顺序：`roots` 参数 → 环境变量 `ADS_AGENT_WORKSPACE_ROOT` → 最近工作区父目录 →
  最近工作区自身 → `~/ads_workspaces`、`~/ADS_Workspaces`、`~/Documents` 中**存在**的子目录（不递归）。

## 6 增补（2026-11-04 lead 裁决，覆盖前文冲突处）

### 6.1 `open_workspace`：异常通道 vs 决策态（细化 1.3）
显式传入"看起来是路径"的 `path`（绝对路径，或含 `/` `\`）时**保留异常通道**
（`PreconditionError`，消息必须仍含「工作区目录不存在」「缺少 lib.defs」
「没有可用的最近工作区记录」原文），以兼容既有 `tests/test_open_workspace.py`。
结构化决策态 dict（`ambiguous` / `not_found` / `invalid_path` / `needs_force`）
只用于**名称片段、父目录扫描、recent 记录**解析出的候选。理由：显式路径给错是
调用方错误，按 4xx 报错更诚实；片段解析缺的是用户决策，必须回 dict 让模型去问。
其余决策态细节：`ambiguous` 候选按 last_used 倒序、name 升序，最多 10 条且绝不
替用户选；`invalid_path` 只出现在"解析到了目录但缺 lib.defs"，此时绝不调用
`de.open_workspace`；`needs_force` 仅在"解析出有效目标 + 当前打开了不同工作区 +
force 缺省"时返回；同一路径已是当前工作区 → 沿用 `already_open`，不传 force。
