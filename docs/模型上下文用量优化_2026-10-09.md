# 模型上下文用量优化（2026-10-09）

旧版圆环展示的是全局 `context_budget_chars` 裁剪预算，接口报告的 token 用量仅在提示中附带显示。字符数不能直接除以模型 token 容量，也不能将所有模型使用同一个分母。

## 新行为

- 以当前聊天、当前模型为索引保存最近一次请求统计，模型容量独立解析。
- 提示中明确模型名、tokens 用量、容量来源、实测或估算状态。
- 接口提供合法 `prompt_tokens` 和 `completion_tokens` 时，显示最近一次请求输入加输出；不把多次模型调用的累计计费量当上下文占用。
- 未返回 usage、生成过程中、输入草稿变化、切换到尚无统计的模型时使用近似估算并标明。后端估算包含实际请求的消息及工具定义；前端尚未发送的历史估算注明不含系统提示和完整工具结果。
- 模型容量未知时显示“模型容量未知”，不展示容量百分比，也不从模型名称猜测上限。
- 聊天历史继续共用。一个模型追加新消息后，其他模型的旧请求统计失效；切回时从更新后的历史重新估算。
- 设置页增加“当前模型上下文上限（tokens）”：填写正整数为该模型覆盖值，留空恢复自动识别。保存供应商连接或多模型列表时保留各模型各自的值，新模型不继承其他模型的容量。
- 修改模型上限或 API 地址后，旧统计失效；迟到的旧设置事件不覆盖新设置。删除聊天、清空聊天仍按原有隔离规则处理。
- 圆环接近容量时改变颜色并提示清理历史或切换模型；未知容量只有背景环。

## 边界

token 估算是 UTF-8 长度的启发式计算，不是各模型专用分词器。不可将估算当成精确实测，也不据此自动扩大请求。现有全局字符裁剪预算是独立的本地历史管理策略，保持其原有裁剪行为，在提示中单独标出。容量百分比表示最近一次请求及其输出相对模型窗口的比例，不代表下一次请求一定会通过服务端限制。
