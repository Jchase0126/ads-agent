# 原厂模型 Include 与 "能不能仿真" 的判据（2026-11-05）

本篇记录 MuRata 套件在 `DAB_ATX_wrk` 里踩到的第二类问题：**模型放得进去、料号也配得上，
但网表里一条 `#include` 都没有**，于是仿真报 `undefined model` / coded model 加载失败。
以及修完之后，`MURATA_SMOKE` 真跑出来的证据。

> 口径纪律：`能放置`、`能落盘`、`料号能配` 是三件事；`能仿真` 必须以
> `run_simulation` 产出数据集 + `read_dataset` 读到有限 S 曲线为准。本轮的
> `MURATA_SMOKE` 已经跑到后者，但**只对这一颗设计、这一版库**成立。

## 1. 现象：INC1 是空表

`DAB_ATX_lib:MURATA_SMOKE:schematic` 当时有 6 个实例：PORT1/PORT2（TermG）、
`LQW18AN_00:Lm`（PartNumber=37）、`GJM15:Cm`（PartNumber=341）、SP1（S_Param
100–300 MHz / 5 MHz）、以及 `INC1 = ads_simulation:NetlistInclude`：

```
IncludePath  = ['']
IncludeFiles = [['', '']]
UsePreprocessor = 1
```

生成的网表里没有任何 `#include`。原因不是 ADS 坏了，而是**通用 Include 只有在
`IncludeFiles` 里有真实文件时才输出 `#include`**；`[['', '']]` 是 ADS 给新实例的
占位，空表就是零包含。

## 2. 两套 Include 机制（都是实测）

| 机制 | 元件 | 网表输出 | 覆盖范围 |
| --- | --- | --- | --- |
| 原厂 Include | `muRataLibWeb_L:muRataLibWeb_L_Include`（0 引脚） | `#ifndef muRataLibWeb_L` + `#include "<models>/*.net"` + `#endif` | 该库 `circuit/models` 下**全部** `.net` |
| 通用 Include | `ads_simulation:NetlistInclude` | 仅按 `IncludeFiles` 逐条 `#include` | 你在表里写的文件 |

原厂 Include 的机制在 `muratalibweb_l_eia_confidential/de/ael/TechInclude.ael`：
netlist 回调 `get_dir_files(<LIB>_CIRCUIT_MODEL_DIR, "net")` 遍历目录，所以参数栏里
看不到文件名，判断"有没有覆盖"要按该库 `circuit/models` 的文件全集算。

### 2.1 相对路径坑（血泪）

`NetlistInclude.IncludeFiles` 是**按工作区相对路径**解释的，生成网表时 ADS 会自己拼上
工作区根目录。第一版实现写绝对路径，网表里出现：

```
#include "E:\ADS\Work_AI\DAB_ATX_wrk\E:\ADS\Work_AI\DAB_ATX_wrk\...\encode.net"
```

即双前缀，文件当然不存在。正确写法：

```
IncludeFiles = [[
  "ads_agent_models/extracted/pkg_.../muratalibweb_l_eia_confidential/circuit/models/encode.net", ""
], [
  "ads_agent_models/extracted/pkg_.../muratalibweb_c_confidential/circuit/models/encode.net", ""
]]
```

网表随后变成 `<ws>\ads_agent_models\...\encode.net`（真实绝对路径）。代码里由
`_include_entry_path()` 负责；比较覆盖时反向用 `_resolve_include_path()` 还原。

## 3. 代码改动

### 3.1 `addon/ads_agent/model_ops.py`

- 新增 Include 识别/归一工具：`_include_role`（vendor / generic / 空）、
  `_include_param`、`_include_pairs`（兼容 SDK list 与字符串 `[['', '']]`）、
  `_include_files`、`_file_key`、`_netlist_includes`、`_include_entry_path`、
  `_resolve_include_path`、`_vendor_net_files`。
- 重写 `prepare_design_dependencies(design, ws_path, place_includes=...)`：
  1. 先认设计里已有的 Include 实例；
  2. `place_includes=True` 时**就地**给空的 `NetlistInclude` 填/追加该库的 `.net`
     （SDK 没有删除实例的 API，只能原地改）；
  3. 只有"这批文件完全没被任何 Include 覆盖"时才追加原厂 Include 元件
     `MODEL_INCLUDE{n}`，**绝不重复包含同一份模型定义**；
  4. 只读预检（`place_includes=False`）缺 Include 时报错文案点名空表、并提示
     `repair_model_includes`。
- 新工具 `repair_model_includes {library, cell, view?, dry_run?}`：开写句柄 →
  补齐 Include → 保存 → **重开只读重新生成网表**，逐条核对 `#include` 是否真的
  指向包内文件；`missing` 非空就是没修好。`dry_run` 只报 `would_fill`，不改盘。
- `read_dataset` 之外不涉及。

### 3.2 `addon/ads_agent/ads_ops.py`

- `build_schematic` 保存后复核：网表 0 条 `#include` → problem（点名
  `repair_model_includes`）；有 include 但缺文件 → 列出缺哪条。
- `run_simulation` 启动 `hpeesofsim` **之前**做同样的复核，缺则直接
  `RuntimeError("仿真前检查未通过 …")`，不让它跑出一个必然失败的仿真。
- `read_dataset` 支持 `块名.列名` 表达式（`SP1.SP.S(1,1)`），`S[1,1]` 与 `S(1,1)`
  视为同一列；只给块名时返回整块统计量；块里没有该列时报错并提示正确写法。
- `_set_param`（上一轮）继续拒绝不在选项表里的料号值。

### 3.3 后端

- `backend/model_tools.py` / `backend/tools.py`：新增 `repair_model_includes`
  （timeout 180）与 `search_model_parts`；`read_dataset` 说明补充"块.列"。
- `backend/agent.py` 纪律第 27 条：原厂模型必须有 Include；空表等于没模型；
  没跑出数据集不许说"能仿真"。

## 4. 实测证据（MURATA_SMOKE）

修完 Include 后（INC1 已填两条工作区相对路径），经 toolserver 8763 调
`run_simulation {library:DAB_ATX_lib, cell:MURATA_SMOKE, view:schematic}`：

- `status = done`，数据集
  `E:\ADS\Work_AI\DAB_ATX_wrk\ads_agent_sim\MURATA_SMOKE_20261105_150815\MURATA_SMOKE.ds`
- 同目录 `netlist.ckt` 里两条 `#include` 都指向包内 `circuit/models/encode.net`，
  元件行为 `LQW18AN_00:Lm … PartNumber=37`、`GJM15:Cm … PartNumber=341`；
- `read_dataset` 读到块 `SP1.SP`：41 点，freq 100–300 MHz；
  - `S[1,1]`：0.686（100 MHz）→ 0.045（300 MHz）
  - `S[2,1]`：0.314（100 MHz）→ 0.955（300 MHz）
  - 即串联 18 nH + 10 pF 的谐振上升沿（f0 = 1/(2π√(LC)) ≈ 375 MHz），
    与电路拓扑一致，不是"能跑但数值是死的"。

## 5. 推荐用法

1. 放完原厂元件后，先确认设计里有 Include 实例（原厂 `*_Include` 或通用
   `NetlistInclude`）。
2. `repair_model_includes {library, cell, dry_run:true}` 看会改什么，再去掉
   `dry_run` 执行；返回 `missing=[]` 才算 Include 就绪。
3. `run_simulation` → 数据集路径 → `read_dataset`（表达式用 `SP1.SP` 或
   `SP1.SP.S(1,1)`）读 S 曲线。
4. 只有第 3 步成功，才能对用户说"该模型在本机仿真通过"。

## 6. 限制

- 只读原厂库，改动只发生在工作区设计的 Include 参数上。
- 只对 MuRata L/C 实机验证过；其它套件若用同一套 Include 机制可复用，但
  **不要据此宣称已逐家验证**。
- 改了 `backend/*.py` 后需重启后端进程，LLM 端才看得到新工具/新提示词；
  ADS 侧 toolserver 会按 mtime 热重载。
- 原厂 Include 元件本身没有文件参数，工具只能按"该库 models 目录全集"判断覆盖；
  用户若手工往 `circuit/models` 里加文件，需要重跑一次 repair。

## 8. 本轮收口补的两处修复（含实测）

1. `read_dataset` 的表达式解析：数据集顶层变量只有块名（`SP1.SP`），块内列是
   `S[1,1]`。现在 `SP1.SP.S(1,1)`、`SP1.SP.S[1,1]`、以及**只有唯一块时的裸列名**
   `S(2,1)` 都能解析；指定列时 `columns` 只报命中列，`stats`/`sample_rows` 连
   `freq` 一起给（否则读到的 S 曲线没有横轴）。实机复读 151231 数据集：
   `S[1,1]` 100 MHz = 0.68585 → 300 MHz = 0.04545，`S[2,1]` 0.31415 → 0.95455，
   41 点（100–300 MHz，5 MHz 步进）。
2. 原厂 Include 幂等：`prepare_design_dependencies` 现在先登记设计里已有的原厂
   Include 实例（按 `(库, Include cell)`），命中就不再追加第二个包含件——否则
   第二次 build 会多出 `MODEL_INCLUDE2`，同一批模型定义被 include 两次，
   hpeesofsim 会报重复定义。
