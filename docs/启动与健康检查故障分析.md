# 1.1.0 / 1.1.1 启动与健康检查故障

## 结论

用户提供的 `ads-agent-1.1.0-fixed.rar` 包含原版、修复版与故障说明。
逐文件对比确认补丁只修改四个运行文件的九处调用，两个根因都存在于官方 1.1.1 源码。
问题不是用户未通过某种使用资格校验，也不是需要删除健康检查或接口鉴权。

| 故障 | 原因与影响 | 修复 |
| --- | --- | --- |
| 工具服务和面板无法启动 | `from qtcompat import QtCore` 取到获取函数；随后调用 `QtCore.QTimer()` 抛出 AttributeError。八处误用影响自动打开、工具服务、错误对话框和窗口查找。 | 显式调用 `qtcompat.QtCore()` / `qtcompat.QtWidgets()` 获取实际模块。 |
| 健康后端被报告为离线 | 启动器先拼 `/health`，探测函数又拼一次；实际请求 `/health/health`。此路径不是公开健康端点，被接口鉴权返回 401，启动器反复探测并最终超时。 | 启动器只传根地址；探测函数同时接受根地址与完整健康地址，保证只拼一次。 |
| 被误报为另一 ADS 版本 | 空目录经过 `normpath('')` 变成 `.`，与另一端实际目录比较后误报冲突；服务身份也未包含当前 ADS 目录。 | 空值保留为空；双方提供目录时才比较，身份上报实际 HPEESOF_DIR。 |

## 为什么之前测试通过

旧工具服务测试直接创建 HTTP handler，验证响应格式和归属，但没有走
`ensure_started()` 的真实 Qt 定时器初始化路径。Qt 适配测试验证获取函数本身，
没有覆盖所有调用者。后端探测测试直接使用服务根地址，也没有经启动器调用。
因此完整离线测试通过仍不足以覆盖上述跨模块连接点。
此前 ADS 2027 开发目录与发布兼容目录的运行代码不同，开发面板可用也不能证明发布包可用。

## 新增验证

- 真实 offscreen QApplication：启动工具服务、验证 QTimer、探测身份、重复启动、关闭并重绑同一端口。
- 真实 HTTP 健康端点：根地址、尾斜杠、完整健康地址均只请求 `/health`；启动器复用健康后端且不产生新进程。
- 代码检查：禁止把 qtcompat 的三个获取函数直接导入后当模块使用。
- ADS 目录矩阵：双方缺失、单侧缺失、相同目录及不同目录分别验证。
- 原有其他服务、其他安装、协议不匹配及接口令牌拒绝测试继续保留。

压缩包中的 ADS 2026 Update 1 实机结果为贡献者提供的记录，本环境未重复该版本验收。
该记录证明其修复包能启动和调用只读工具，不代表已完成所有建图及仿真验证。
ADS 2024–2026 的实验性写入门禁保持原有设置。
