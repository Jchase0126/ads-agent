# PDF 模型封装失败诊断与解决方案

检查日期：2026-10-21。范围：当前源码、本机实际日志、持久化模型与仿真记录、已有验收产物，以及针对性离线测试。本轮只诊断并编写方案，未修改运行代码、当前 ADS 设计或模型库。

## 1. 结论

目前具备“把已有模型修订导入 ADS、生成三脚 symbol、建立使用电路并仿真”的能力；“从聊天上传 PDF 开始，自动生成并封装模型，完成可信验证，再跨工作区复用”的完整流程仍未打通。

10 月 20 日的聊天实际经历了两条不同路径：

1. 08:29–08:34：从 PDF 建模失败，参数存档多次被拒，未取得可用曲线，未生成模型记录。
2. 09:03–09:04：检索并导入之前验收时生成的 candidate 修订，封装与仿真成功；随后模型验证因 ID 错配失败。后续多轮重复同一错误。

因此“已有元件能跑仿真”成立，但不能据此认定“本次 PDF 自动建模完成”或“模型准确度已通过”。当前重点应是打通身份、证据归档、复验和聊天编排；单独修改提示词或重新画 symbol 无法解决全部问题。

## 3. 已确认根因

### P0-A：两种 model_id 混用，接口没有充分区分

`backend/device_models.py:365` 的 `_path()` 只接受 64 位十六进制建模记录 ID；模型库使用 `mdl_…` 稳定身份。二者都叫 `model_id`，聊天将库 ID 传给 `get_device_model` / `validate_device_model`，必然失败。

本轮只读复现：

- 传 `mdl_fa78e470d5baab49` → “无效的模型记录 ID”。
- 改传清单中的 64 位 `source_record_id` → “模型记录不存在”。

第二条说明只替换 ID 不够，还存在下一项恢复问题。

### P0-B：验收数据根与运行数据根隔离，修订没有完整恢复材料

当前用户数据根没有 `datasheets/models` 和 `datasheets/curves` 目录。源记录实际保存在：

`output/device_library_acceptance/data/datasheets/models/e1bf566b30d0b4387713dedd18a1604bffde3d9aea592e3b6facfb86fbf9ce6a.json`

同一验收数据根还保留 16 份曲线和参数记录，原始证据并非全部丢失。

`backend/device_library.py::_write_staging()` 归档了 PDF、证据引用、元件计划、验证计划及依赖，但没有完整归档源模型记录、拟合候选及曲线记录。`get_model_revision()` 还能隐藏部分参数来源内容。发布后的资产可以建元件，却不能独立支撑现有 `validate_device_model()` 所依赖的记录读取与曲线比较。

### P0-C：验证工具 schema 与执行契约冲突

`backend/device_models.py` 的 `validate_device_model` 工具定义仍向聊天声明 `simulation` 对象；执行函数约 1496 行却明确拒绝 `args['simulation']`，要求可信 `simulation_id`。部分建模返回提示也仍示范 `simulation=...`。

日志中的聊天确实按旧契约填写了 `simulation`。目前先被错误 ID 拦住；即使修正 ID 并恢复源记录，仍会遇到这个障碍。会话注入函数会清除调用者自填来源；修复时应统一 schema、返回提示、会话注入与直接调用契约，不能依赖某一入口悄悄补救。

### P0-D：导入后的使用电路没有修订级复验绑定

源记录的建图目标是 `AI_lib:J310_ACC_617b300b`，扫描步长 5 MHz；10 月 20 日仿真的目标是 `J310_work:SMMBFJ310L_use`，使用电路取 201 点，步长 4.5 MHz。

`backend/agent.py::_record_simulation()` 主要从调用参数中的建模记录 ID 尝试提取指纹；导入、放置返回的数据没有形成完整的 revision → placement → build → simulation 绑定。现有验证还会按原模型记录中的库/cell 对比仿真目标，恢复源记录后也不能直接把旧建图记录套到新的使用电路上。

需要为“源模型验证”和“已封装修订在新工作区复验”分别建立执行绑定，同时共用数值和证据检查。

### P1-A：PDF 前处理依赖聊天手填复杂证据，错误不能有效收敛

08:32:45 在无曲线时先调用建模；08:33:45 的通用曲线请求缺 `port_order`，各矩阵元素也没有采用已复核样本的独立映射。当前文件 SHA 与 `sample_adapters.py` 中的 `smmbfj310l_v1` 完全一致，已有可靠样本路径，但聊天没有选用。

参数保存中 `mmhos` 被当作输入单位传入，而数值单位表只接受 `mS` 等规范单位；原文证据应保留 `mmhos`，数值字段应归一化。`_UNIT_TOKENS` 字典还存在重复 `uS/µS/μS` 键，后面的定义会覆盖前面的别名，需要合并并测试。

这些证据门禁不应取消。应增加确定性适配器选择、单位归一化、必填预检和结构化错误修复；未知 PDF 必须经过轴、图例、端口和条件复核，不能凭型号套用样本路径。

### P1-B：未验证模型被错误标为“使用模型已验证频段”

`backend/device_library.py::usage_plan_from()` 在显式传 `band_hz` 时直接设置该标签，没有检查 validation。

本轮只读调用该函数已复现：输入 `status=candidate`、`validation={}`、`band_hz=[1e8,1e9]`，输出仍是“使用模型已验证频段”。10 月 20 日的日志也出现相同结果。

应分别返回 `requested_band_hz`、`source_curve_band_hz`、`validated_band_hz`、`validation_status`；显式请求频段不能变成验证证据。

## 4. 推荐实施方案

按以下依赖顺序修复，不建议先扩大通用器件族支持。

| 顺序 | 改动 | 完成判据 |
| --- | --- | --- |
| 1 | 将建模记录身份明确为 `model_record_id`，库身份为 `library_model_id`，保留旧字段兼容；统一验证工具 schema，删除自填 `simulation` 的示例，接受可信 `simulation_id` | 错用 ID 返回明确类型错误和可执行下一步；工具定义与实现一致 |
| 2 | 修订归档增加模型记录、拟合结果、参数与曲线快照、解析来源和各文件 SHA；引入归档版本及严格完整性检查 | 在全新用户数据根，仅凭修订包即可读取模型与证据；源输出目录不可见时仍能复验 |
| 3 | 增加 `validate_device_revision(revision_id, placement_id, simulation_id, thresholds)` 或等价后端接口；由后端从真实导入和建图回执生成绑定 | 新工作区使用电路可复验；错误 revision、参数改动、数据集替换、错误公共端均被拒绝 |
| 4 | 将 PDF 建模变为持久化分阶段流程：文档检查→适配器/证据→曲线复核→候选→拟合→建图→仿真→验证→发布 | 前置缺失不执行后续步骤；服务重启可以恢复；失败回到明确阶段 |
| 5 | 修复频段标签、合并单位别名、改进工作区预检与错误字段 | candidate 不出现“已验证”；原文与规范单位分开保存；无工作区时不进入导入建图 |
| 6 | 用真实面板入口验收并修正文档 | 上传到发布完整走一次；重启、全新数据根、跨工作区再次验证 |

修订复验需要同时检查：真实使用电路的网表与端口映射、模型规格指纹、修订文件指纹、仿真来源、数据集 SHA、频段及偏置条件。不能简单把源记录的 library/cell 改成新名字，也不能只允许任意 cell 通过。

精度阈值应在拟合/验收前明确保存，S 与 Y 分量纲。缺阈值可以输出误差和 `validation_incomplete`，不能为得到 published 状态自动放宽阈值。

旧修订应通过新归档版本或独立、带摘要绑定的迁移记录补齐；不要直接覆盖已有不可变修订内容。旧记录无法恢复的部分应标缺失，并重新提取或复核。

## 5. 当前样本的最短恢复路径

1. 保留现有 candidate、ADS 单元和数据集。
2. 从 `output/device_library_acceptance/data/datasheets` 读取源模型、曲线、参数与文档快照，逐项核对它们与修订的 document_id、curve_ids、source_record_id 和元件参数是否一致。
3. 在隔离恢复数据根准备证据，补成新的可复验归档版本。不能仅迁移一个 JSON 就宣称恢复完成。
4. 先用原始验证计划建立独立新 cell，接入标准仿真和可信来源绑定，完成源模型验证。
5. 再在另一个新工作区导入封装元件，通过新增修订复验接口检查同一规格与端口对应关系。
6. 将“能放置”“能仿真”“数值等价”“与手册误差达标”分别报告。只有必需项通过才升级为 published。

该样本的范围是指定偏置（VDS=10 V、ID=10 mA、25°C）下约 100–1000 MHz 的小信号模型；现有资料和实现不支持宣称任意偏置的完整非线性 JFET、噪声或温度模型已完成。
