# 用对话创建与打开工作区（使用说明）

> 适用于 1.3.5 之后的开发版。工作区的新建与打开都可以直接对 ADS Agent
> 说一句话完成，不需要先退出对话去 ADS 菜单里操作。本文说明三步用法、
> 目录解析规则、切换风险以及每种失败原因该怎么处理。
>
> 相关契约：[工作区对话式创建与打开_接口契约_2026-11-04.md](工作区对话式创建与打开_接口契约_2026-11-04.md)

## 一句话上手

- 新建：「新建一个叫 5G_PA 的工作区」
- 打开：「打开我之前那个滤波器工作区」
- 切换：「切到 5G_PA」

模型会先用工作区工具确认目标，再把真实的路径、库列表和结果告诉你；
不会用脚本手工建目录，也不会扫盘猜路径。

## 三步操作

### 第一步：新建工作区

直接说「新建一个叫 XXX 的工作区」。模型会先问清两件事：

- 名称：目录名，也就是工作区名。不能为空，不能是 `.` 或 `..`，不能含
  `\ / : * ? " < > |`，最长 120 个字符。
- 位置：父目录。你直接给路径，或者说「默认位置」，也可以只说「放
  D 盘的 ADS_Workspaces 下」。

信息齐了模型会调用 `create_workspace`，创建目录（默认同时建一个与工作区
同名的首个库并写入 `lib.defs`）并打开。成功后会如实回报：

- `path`：工作区目录的真实路径
- `libraries` / `writable_libraries`：挂载的可写库
- `workspace_open`：是否已打开

已存在的目录绝不会被覆盖或清空：不带 `force` 时会直接返回 `exists` 拒绝。

### 第二步：打开已有工作区

直接说「打开滤波器那个工作区」即可，不必记住完整路径。模型会先调用
`list_workspaces(query="滤波器")` 做有界发现，然后把候选按
名称 / 路径 / 最近使用时间列给你选：

- 只有一个候选：模型可以直接打开它，并把路径告诉你。
- 多个候选：必须列给你选，不会替你挑一个。
- 你本来就记得完整路径：直接说路径，模型按路径打开。

发现只扫已知的根目录（最近工作区、配置根、`~/ads_workspaces`、
`~/ADS_Workspaces`、`~/Documents` 下存在的子目录等），每个根只扫 1–2 层，
单根条目过多会跳过并提示 `truncated`，绝不会 `os.walk` 全盘或遍历盘符。

### 第三步：切换工作区

当前已经打开另一个工作区、你说「切到 5G_PA」时，模型会先明确提示：

> 切换会关闭当前工作区，未保存的修改会丢失。

你明确确认后它才会带 `force=true` 切换；没有确认不会切。切换是「关闭
再打开」，不是并存——同一个 ADS 进程同时只有一个工作区。

## 根目录解析顺序

新建工作区时，父目录按以下顺序确定（前者优先）：

1. `create_workspace` 的 `root` 参数（你直接给的位置）
2. 环境变量 `ADS_AGENT_WORKSPACE_ROOT`
3. 最近工作区的父目录
4. 数据根目录下的 `workspaces`（默认 `%LOCALAPPDATA%\ADSAgent\workspaces`）

数据根目录可用环境变量 `ADS_AGENT_DATA_DIR` 覆盖。

## 最近工作区记录

每次成功新建或打开后，都会记录到：

- `%LOCALAPPDATA%\ADSAgent\recent_workspaces.json`：结构为
  `{"version": 1, "items": [{"path": ..., "name": ..., "last_used": ...}]}`，
  最多 20 条，最近的排在最前，去重后原子写入。删除该文件只会丢失
  「最近」提示，不影响已建的工作区。
- `%LOCALAPPDATA%\ADSAgent\last_workspace.txt`：与旧版本兼容的记录，
  仍会同步更新。

## 切换风险

- 切换 = 关闭当前工作区 + 打开目标工作区。未保存的设计、变量、原理图
  修改都会丢失。
- 模型在切换前必须得到你的明确确认；如果它没提示就直接切换，属于异常，
  请立即停止并回报。
- 打开已有目录（而不是新建）同样受此约束：目标已存在、当前又有其它
  工作区打开时，不带 `force` 会返回 `needs_force`。

## 失败原因对照表

`create_workspace` / `open_workspace` 失败时返回 `created: false` 或
`opened: false`，并带一个 `reason`。模型必须原样转述原因，不能把失败说成
成功。

| reason | 含义 | 你该怎么做 |
| --- | --- | --- |
| `exists` | 目标目录已存在，且没有带 `force`；工具不会覆盖已有工作区 | 想继续用这个目录就确认后重试（带 `force`），或换一个新名称 |
| `needs_force` | 当前已打开另一个工作区，切换前需要你确认 | 确认「会丢弃未保存修改」后重试，模型会带 `force=true` |
| `invalid_name` | 名称为空、是 `.`/`..`、含 `\ / : * ? " < > |` 或超过 120 字符 | 换一个合法的目录名 |
| `invalid_path` | 路径是文件、父目录不存在或不可写；打开时还可能是目录里没有 `lib.defs` | 检查路径拼写与权限；打开时确认该目录是 ADS 工作区根目录 |
| `sdk_unsupported` | 当前 ADS 版本的 SDK 没有 `create_workspace`（2024–2026 为实验性适配，2027 已验收） | 在 ADS 里手动新建工作区，再让模型打开它 |
| `ambiguous` | 名称片段命中多个工作区 | 按模型列出的候选（名称/路径/最近使用）选一个，或给出完整路径 |
| `not_found` | 名称片段没有命中任何已知工作区 | 检查名称或直接给出完整路径 |

`ambiguous` 会附带 `candidates` 列表；`not_found` 说明已知根里确实没有。
这两种情况模型都不会替你猜一个。

## 都失败时的手动兜底

「请在 ADS 中手动打开 Workspace」已不是首选建议。只有
`create_workspace`、`list_workspaces`、`open_workspace` 三个工具都失败，
或 SDK 明确不支持时，才由你在 ADS 菜单里手动新建/打开工作区；此时模型应
把失败原因和原始 `message` 一并告诉你，方便排查。
