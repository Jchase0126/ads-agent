# PDF 交互建模审查与优化提示词

审查日期：2026-10-13。范围：当前源码中的 PDF 附件、参数存档、模型生成、聊天工具和样本 ADS 执行流程。此文档是审查和后续实施任务，不表示下面的新功能已经实现。

## 审查结论

当前产品完成了文本上传和无源模板链路，尚未完成通用的“PDF → 有源器件模型 → ADS 验证”交互链路。J310 样本的有源反推及 FM 电路确实执行过，但它们是经过人工图形复核的专用脚本，不是聊天工具已经具备的通用能力。文件卡片改善了显示，没有补齐解析或建模能力。

本次运行现有测试：`test_datasheet_models.py` 8 项、`test_model_attachments.py` 61 项，均通过。真实 SMMBFJ310L PDF 仍返回 `page_count=14`、`parameter_extraction_safe=false`。这 14 是文本流计数，原文件实际为 5 页。

## 发现与优先级

| 优先级 | 发现 | 源码依据 | 影响 |
|---|---|---|---|
| P1 | PDF 原文件没有持久化 | `backend/server.py:680`、`backend/datasheet_models.py:95` | 上传后仅剩抽取文本，不能按 document_id 重新读取页面、曲线或修复字体解析 |
| P1 | 解析器扫描文本流，不解析完整页树/字体编码 | `backend/pdf_extract.py:174`、`:206` | 负号、微单位、列对应不可靠；页数误报；该 J310 的建模门禁合理阻止继续 |
| P1 | 聊天建模工具只生成串联 RLC | `backend/datasheet_models.py:210`、`:276` | JFET 被明确拒绝；没有聊天可调用的有源反推、S2P 生成或模型导入接口 |
| P1 | 样本脚本未接入运行模块和工具注册 | `tools/extract_j310_curves.py`、`tools/fit_j310_physical.py`；`backend/tools.py:902`、`release_manifest.py:35` | 研发样本成功不能转化为已安装 ADS Agent 的交互能力 |
| P1 | 参数记录缺乏页码、区域、表格结构与语义复核流程 | `backend/datasheet_models.py:136` | 数字和单位在引用里出现，不代表属于同一行/列或同一测试条件；状态仍为 extracted_unreviewed |
| P1 | JFET 必要单位尚不支持 | `backend/datasheet_models.py:21` | 本次实际调用 quantity 确认 mS、uS、psec、nV/sqrt(Hz) 被拒绝；影响 gm/gds、延迟与噪声参数存档 |
| P2 | 阶段状态未统一到建模任务 | `addon/ads_agent/panel.py:3330`、`:4351` | parsed 或 sent_file 只说明解析/显示；没有持续可查的候选、拟合、建图及验证状态 |
| P2 | 待发送附件仅保存在内存 | `addon/ads_agent/panel.py:1366`；现有测试明确不持久化 pending 队列 | 重启后卡片可能还在，但待发送关系无法自动恢复；需定义恢复/过期语义 |
| P2 | 文件卡片不等于原生 PDF 或视觉上下文 | `addon/ads_agent/panel.py:4351`、`model_attachments.py:49` | 模型仍收到文本摘录，页面图像、曲线及原始 PDF 没有进入模型请求 |
| P2 | 示例优化目标写死 | `tools/design_fm_fet.py:44` | 示例按约 8 dB 综合；不能直接复用来完成“全 FM 频段增益 >15 dB”的新要求 |

P1 表示会阻断或明显降低核心能力；P2 表示交互、复现和目标一致性问题。不能通过放宽字体门禁、改提示词宣称“已解析”来解决 P1。

## 可直接交给工程代理的详细优化提示词

```text
你正在维护 Windows 上的 ADS Agent 工程：D:\Antenna\ADS Agent。
用户希望在聊天窗口发送元器件 PDF 后，通过交互完成有证据的参数提取、模型选择、ADS 建模和真实仿真验证。
当前 ADS 安装为 E:\ADS\Programfile\ADS2027；用户工作目录为 E:\ADS\Work_AI。

请先读取当前源码和 docs/PDF交互建模审查与优化提示词_2026-10-13.md，按下面阶段实施优化。
保留工作区现有修改与成功工程，不覆盖已有原理图，不清空会话、配置或模型资产。
本任务要求改代码并完成指定样本的端到端验证，不能只修改系统提示或 PDF 卡片样式。

一、建立真实文档资产和证据接口
1. 把上传的 PDF 原始字节按内容 SHA-256 存入后端统一数据根目录，使用原子写入和去重。
2. 文件名只用于显示；存储路径由服务生成。记录资产版本、大小、来源和所属聊天/项目，兼容旧的纯文本记录。
3. document_id 能用于按页读取文本、页面图像、表格和图形证据。限制页面渲染尺寸、页数、内存和返回体积。
4. 原始 PDF 是本地资产。是否向远端模型发送 PDF 或页面图像，由配置、模型能力和现有用户授权决定；工具返回应说明实际发送形式。
5. 对旧记录报告 source_unavailable，并提供重新附加路径；不得把摘要当成原始 PDF。

二、修复 PDF 解析，而不是解除校验
1. 使用具备页树、对象流和字体编码解析能力的成熟 PDF 库，取得真实页数和逐页文本/坐标。现有标准库解析器仅作受限降级。
2. 正确处理 ASCII/Unicode 负号、µ/μ/u、上标和工程单位；保留原始字形文本与规范化值的对应关系，不能凭器件常识恢复缺失符号。
3. 表格提取保留行、列、单元格、表头、Min/Typ/Max、型号列、脚注和测试条件。多型号手册须先选定具体型号。
4. 使用页面/区域级可靠性状态；无法可靠提取的字段进入 requires_review，不得将全文设置 safe=true 来绕过失败。
5. 原生矢量图优先提取；扫描图采用 OCR 或经能力确认的视觉读取。OCR/视觉结果仍需证据和数值核对，不自动等于 verified。
6. 前台只能显示真实页数；未知时显示未知，不把内容流计数叫 PDF 页数。

三、定义参数、曲线和模型三种不同记录
1. 参数至少含：document_id、具体型号、符号、原文、数值或范围、单位/SI、Min/Typ/Max、类别、测试条件、页码、bbox、解析方法、复核状态。
2. 增加 S/mS/µS、时间 s/ns/ps 和明确的噪声谱密度单位；频率、温度、VDS、VGS、ID 等条件以结构化字段保存。
3. 提取值、拟合值、工程假设分开保存。拟合 gm/R/L 等值不能被伪装成厂家原文直接给出的值。
4. 曲线记录保存图号、轴名称/单位、线性或对数刻度、刻度校准点、采样、幅相定义、偏置、温度、公共端、端口顺序和参考阻抗是否已声明。
5. 增加显式复核流程；复核应针对字段证据和规则，不是一键让不可靠 PDF 全部可信。
6. 未确定的值允许 unknown；最大额定值、最大电容和参数范围不得自动作为标称模型值。

四、按资料选择能成立的模型类型
1. 原厂 SPICE/ADS/Touchstone 文件存在时，优先通过现有模型检查、导入、挂库和依赖校验使用真实模型。
2. 有固定偏置复数 S/Y 曲线时，可以建立该偏置下的数据二端口，或受约束的有源小信号模型。
3. JFET 小信号模型至少允许 gm/gds、Cgs/Cgd/Cds，按证据选择串联损耗、封装电感和响应延迟；不得用纯无源 RLC 代替有源器件。
4. 器件 G/D/S 三端和测试网络的两个端口必须分别描述。物理封装脚号、ADS 原生符号脚号和端口顺序有独立映射表。
5. 资料不足以支撑非线性/DC/温度/噪声模型时，报告这些维度未支持，同时继续完成已支持的小信号模型。
6. 将 tools/ 下已验证的 J310 提取、反推和验证算法整理成运行模块。通用模块不得写死本机临时路径、具体 SHA 或 PDF drawing 索引；SHA 锁定的样本映射可以作为独立适配器与回归数据。

五、把建模引擎接到聊天工具
1. 新增明确的工具契约，例如 inspect_datasheet、read_datasheet_page、extract_datasheet_tables、extract_datasheet_curves、review_parameter_set、prepare_device_model、fit_device_model、build_device_model、validate_device_model。
2. 每个工具输出结构化状态、资产/任务 ID、证据、尚缺数据和适用范围。注册到 backend/tools.py、agent.py、工具服务与发布清单。
3. 建立任务状态：uploaded→parsed→requires_review/ready→candidate_generated→fitted→built→simulated→validated/validation_failed。
4. 不把上传、生成方案、保存文件或仿真结束作为模型验证完成。任一阶段失败都保留已完成阶段与诊断。
5. 计算、拟合和 PDF 渲染放到工作线程/进程；ADS DE 数据库操作按现有主线程约束执行。明确解析、数值库和 ADS Python 的运行环境及依赖检查。
6. 任务须支持取消、重启恢复、重复请求去重和工作区切换；修改目标由发起任务时的可信工作区身份固定。

六、定义模型验证的证据和误差
1. 分开报告：ADS 导入/拓扑一致性、ADS 与独立数值计算的一致性、与手册曲线的拟合误差、模型未验证范围。
2. 拟合、结构选择与最终验证数据分别说明；跨图 S/Y 校验不能当成独立实物测量。
3. 记录目标函数、归一化方式、工程边界、初值、收敛、边界命中、参数敏感性和适用偏置/频段。
4. 若同一批留出点用于模型选择，不将其误称为完全盲测。保留未参与拟合的图表/频点作进一步核对。
5. 阈值依据用户指标或声明的工程规则保存，不能拟合失败后静默放宽。绝对幅差、相对误差、dB 和相位差分别标注。
6. 建图继续执行已有参数读回、逐引脚网表等价、几何、依赖和真实数据集门禁，不得通过 run_python 绕过它们。

七、修复附件交互的完整生命周期
1. 发出后保留右侧 PDF 文件卡片，问题正文正常显示；解析大段文字作为内部上下文或按需检索，避免每轮重复塞入全文。
2. 卡片可查看原 PDF 和解析证据；详细状态可展开，parsed/sent 不应表达已建立模型。
3. 持久化待发送/已发送关系。重启后恢复或明确标为未发送，不允许卡片在但附件无法随消息发送。
4. 同一 PDF 重复上传有不同附件实例 ID，内容资产可共享。发送一个实例不能错误改变同项目内其他未发送实例。
5. 文件-only 消息、发送失败、解析失败、移除附件、项目删除和切换均有明确状态；无正文的附件发送也立即保存会话。
6. 暂不支持视觉输入、OCR 或原文件发送时，应说明具体能力限制，并给出可执行的可靠降级路径。

八、把放大器目标与模型能力绑定
1. 将频段、参考阻抗、全带/中心频率增益、回波、稳定性、允许级数和指定工作目录结构化保存。
2. “FM 增益大于 15 dB”默认需要明确频段内最小值；不能用中心频率值、8 dB 示例目标或预计值宣称达标。
3. 单级候选达不到目标时，给出约束原因并比较多级/其他拓扑。用户未限制级数时可设计多级候选，并验证整体反馈、级间匹配和稳定性。
4. 实际建图、仿真和指标判定引用真实数据集。线性模型不得支持或宣称已验证 P1dB、IP3、噪声系数或真实 DC 偏置。

九、指定样本验收
```
