## 发现与优先级

### P0：验证返回成功缺少必要判据

位置：backend/device_models.py:796、:898、:914、:933；backend/agent.py:455。

validate_device_model 计算 independent_numeric 指标却不据此判失败；没有用户曲线误差阈值时 curve_pass=None，passed 默认 True，最终仍写 validated。Agent 的说明又允许把 validated 表述为验证完成。

本次只读复现：保留真实模型与曲线记录，把全部 S 参数输入替换为零，未给阈值，返回 validated、最大曲线复数 RMSE 约 0.9624。复现通过直接函数的测试注入分支完成，并屏蔽 _save；没有向聊天提交伪数据，也没有覆盖真实模型。聊天入口确实注入 read_traces，但真实仿真读到错误拓扑的数据时，同样存在缺乏判据的问题。

### P0：package_delay 建图漏掉公共端封装支路

位置：backend/device_models.py:117、:645、:662。

数值正演为 g/s/d 三端都加入串联 R、L，再消元得到二端口。ADS 建图只给 port1、port2 加入支路，common 对应的内在 FET 引脚直接接地。J310 共栅测试时因此缺失 Rg/Lg；现有拟合记录 Rg≈2.612 Ω、Lg≈0.527 nH，均非零。这是明确的拓扑不一致，不能通过调大误差阈值消除。

### P1：reviewed 仍不代表语义已核实

位置：backend/datasheet_models.py:669；backend/device_models.py:350 附近。

复核检查数值和单位出现在引用行、条件文本出现在同页，没有校验结构化条件与原文相符，也没有表格型号列/Min-Typ-Max/测试条件的区域关系校验。prepare_device_model 只拒绝 requires_review，没有严格验证所有相关证据归属和复核级别。

只读复现：将已有参数记录 conditions_structured 改成 vds_v=99、id_a=99，保持原引用，review_parameter_set 仍返回 review_passed=true、reviewed。复现屏蔽写入，未修改参数档案。

### P1：曲线矩阵组合与证据归属校验不足

位置：backend/datasheet_curves.py:413；backend/device_models.py:219、:566。

assemble_matrix 校验各幅值曲线频点，却没有逐项比较对应相位曲线频点；重复标签会覆盖；_phase_unit 可能受记录遍历顺序影响；幅值单位被最后记录覆盖。_load_curves 主要检查 configuration，未全面检查 document_id、型号归属、条件、port_order、z0 和复核状态。

只读复现：幅值频点 [100,200] MHz、相位频点 [900,1000] MHz，矩阵仍成功组合并返回 [100,200]。还需对缺失矩阵元素、非法下标、幅相点数、混合量纲、NaN、重复频点和曲线域进行严格检查。

### P1：S2P 参考阻抗写死

位置：backend/device_models.py:743。

函数读取曲线 z0 作为端口阻抗和记录值，写 Touchstone 时却固定头部 # MHz S RI R 50。非 50 Ω 数据将被错误解释。two_port_data 候选允许成对 Y 数据，但构建阶段又明确拒绝仅 Y 的二端口，工具选择承诺也需统一。

### P1：依赖运行时只解决了文本解析

位置：backend/pdf_extract.py:353、:413、:447；backend/device_models.py:63、:72。

runtime_python 子进程只支持逐页文本解析；矢量路径工具仍要求后端本进程有 PyMuPDF，拟合也要求本进程有 NumPy/SciPy。故“上传可解析”不等于“曲线和拟合可执行”。当前 runtime_python 配置为空；本机测试解释器具备依赖，不代表 ADS 实际后端具备。

### P1：通用交互验收不足

tools/acceptance_j310_pipeline.py 直接调用函数，参数来自脚本内人工复核常量、曲线使用 SHA 锁定 preset；tools/acceptance_j310_ads.py 直接调用 ADS API。它们证明样本函数链路，不证明 LLM 通过 HTTP/SSE、工具派发、ADS RPC 完成流程。通用曲线仍要求调用方提供坐标校准和路径索引，扫描图不支持；目前没有完整页面视觉/表格结构工具。

### P2：附件恢复与模型任务生命周期不完整

位置：addon/ads_agent/panel.py:1366、:4358；backend/device_models.py:290、:604、:796。

待发送附件仍为内存队列；现有测试明确要求它不持久化；相同 PDF 以 SHA 区分，缺少每次附加的独立身份。纯文件发送缺少明确的立即持久化步骤。重复 prepare 会重新写记录，重复 build 生成随机 cell；没有统一持久化的 built/simulated 事件、数据集指纹和恢复策略。不能把卡片状态直接视作模型任务状态。

```text
你正在维护 D:\Antenna\ADS Agent。请按当前源码实施 PDF→有源模型交互链路第二阶段优化，先阅读 docs/PDF交互建模复审与下一步优化提示词_2026-10-14.md、适用 AGENTS.md 和相关代码。

目标是让已安装 ADS Agent 通过真实聊天上传 PDF，建立证据可追溯的模型，在 ADS 中仿真并给出可信判定。保留现有原文件存档、逐页解析和有源工具，不重写已经完成的模块，不放宽可靠性门禁，不把样本 preset 当作通用识别能力。

工作区默认 E:\ADS\Work_AI。先完成以下阶段，再处理 FM 放大器匹配和偏置优化。修改前确认当前文件改动，保留用户已有工作。未经实际运行不得宣称验证通过。每阶段提供代码、测试、证据和剩余限制。

阶段一：修复模型拓扑与验证假阳性，最高优先级。
1. 从同一个三端模型规格生成数值正演和 ADS 建图。package_delay 对 g/s/d 全部建立 R/L 串联支路，区分外部公共端与内部公共端；外部公共端接参考地，内部公共端不得越过非零封装支路直接接地。支持 common_gate/common_source/common_drain，保留物理封装脚号与 ADS 符号脚号独立映射。
2. 增加非零公共端 R/L 回归，逐支路核对模型规格、建图参数和网表。不要只按实例数量判通过；用实际 ADS 复数 S/Y 与独立正演核对，确保测试能抓到漏支路或端口互换。
3. 将验证结果拆成 import_consistency、numeric_equivalence、datasheet_accuracy、scope_coverage 四个子结果，各包含 evaluated/pass/fail/not_evaluated、指标、阈值来源、适用域和失败原因。
4. 数值等价检查使用明确且有依据的工程容差；不同量纲分别比较，优先采用归一化误差及必要的绝对误差下限。S 无量纲 RMSE 与 Y 的西门子 RMSE 不得取一个 max 后套同一阈值。
5. 无手册精度阈值时仅报告误差并置 accuracy_not_evaluated；任何必须的等价检查失败必须失败；缺少必要检查不得整体 validated。区分工具执行成功 ok 与模型验收成功。同步 Agent 提示、工具 schema、验收脚本和界面描述。
6. 在读数据前核实数据集由本模型本次建图/仿真产生；绑定 workspace、library/cell/view、模型版本、拓扑/参数指纹、simulation_id、数据集 SHA、频段和时间。不得仅凭任意 dataset_path 关联模型。
7. 所有 real/imag S 参数必须有一致、有限、严格单调的频率轴和等长数据；禁止静默截断或混频。拒绝 NaN/Inf、空数据、异长度、错轴和错误单位。
8. 只在手册曲线与仿真的交集内比较；超域明确标 extrapolated/not_validated，不允许 np.interp 两端常数填充成为达标证据。相位按环绕角差计算，低幅值点明确处理相位可信度。
9. 将全零 S、端口互换、公共端寄生支路缺失、错数据集、超域、无阈值和异常频率轴加入负例；确保这些输入不会得到整体 validated。

阶段二：证据语义与曲线一致性。
1. 表格证据保存 row_id/column_id、表头层级、型号列、Min/Typ/Max、symbol、unit、bbox、脚注及测试条件区域关系。引用中出现数字只算 evidence_checked，不能直接等同 semantic_verified。
2. conditions_structured 每个字段绑定原文 token/区域和单位转换；原文 10 V/10 mA 不得接受 99 V/99 A。不具备语义证据的记录保持 requires_review 或 evidence_checked，不得一键 reviewed。
3. 参数集和所有曲线必须属于目标 document_id 及对应型号；型号共用范围要有声明证据；条件、温度、configuration、port_order 和 z0 必须兼容。不兼容时拒绝拼接；变换或重归一化须显式记录方法及前后数据。
4. curve mag/phase 必须成对、同频点、同元素、同配置与同条件，完整提供 2×2 参数；检查重复标签和非法下标。每条幅值先换算到统一 SI 单位，相位单位单独保存，组装结果不依赖记录顺序。
5. 曲线状态从 digitized_unreviewed 进入复核状态需要明确的轴、图例、路径、偏置和端口证据；已复核 preset 可以作为可信回归适配器，但保留 SHA 门禁和来源，不允许猜路径索引。
6. Touchstone 头部参考阻抗使用实际 z0，支持非 50 Ω 测试；统一 two_port_data 的 Y 支持承诺，正确做 Y→S 或在 prepare 阶段明确阻止并列出缺失能力。

阶段三：统一运行依赖和实际部署。
1. 文本、页面渲染、矢量读取和拟合统一执行后端/受控 worker 协议；支持当前后端缺 PyMuPDF/NumPy/SciPy 而配置运行时具备依赖的场景，不得出现解析可用但下一步仍调用缺库的主进程。
2. 增加只读能力探测，返回各功能 available/unavailable/degraded、解释器路径、依赖版本和原因；错误应由工具结构化返回，不能让 RuntimeError 意外中断对话。worker 有超时、取消和有限输出。
3. 核实实际 ADS 插件和后端 app_root、版本、代码指纹、解释器、工具集合及协议。当前默认安装目录缺新模块，须使用现有部署机制同步完整发布白名单，再确认运行时加载位置；不覆盖用户密钥、配置、会话和工作区。
4. 以仅含发布白名单的隔离目录运行安装后测试，不能靠开发目录 sys.path 或 tools/ 脚本满足功能。依赖安装方式、版本范围和自检说明须随发布交付。

阶段四：完善通用 PDF 交互与任务恢复。
1. 增加按 document_id/page/bbox 获取页面图像的能力，与当前 LLM 多模态协议做能力协商；明确本地读取与向模型服务发送图像的区别。无法视觉识别时提供证据界面或明确缺失，不用猜测填表/校准。
2. 提供表格结构提取和曲线定位候选；矢量曲线优先，提供图号、轴刻度、图例与路径叠加预览。扫描图只有真正接入 OCR/数字化能力后才能声明支持。候选置信度不足时保留 requires_review。
3. 模型流程用持久化 task_id 管理，并引用 document_id、parameter_set_id、curve_id、model_id；分别记录 parsed/evidence_checked/candidate_ready/fitted/build_planned/built/simulated/validation_reported/validated/failed/cancelled。依据真实执行事件迁移，重启可恢复，重复请求幂等。
4. 相同 PDF 共用内容 SHA，但每次附件有 attachment_instance_id。待发送状态持久化或明确过期；重启、纯附件发送和项目切换不得丢失关联或重复发送。发送成功立即保存，卡片不展示长文本，展开后可查看原 PDF、解析质量及任务状态。

1. 上传 tests/fixtures/SMMBFJ310L.pdf，经面板→HTTP 上传→聊天上下文→工具调用→ADS RPC→真实 .ds 读取→验证报告完成流程。不能以直接调用 Python 函数代替整条交互验收。
```
