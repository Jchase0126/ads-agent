### 1. 用户流程和实现范围

用户发送 ZIP → 原包独立保存到当前 ADS Workspace 的模型资产目录 → 用户点击“解压并导入”或明确要求导入 → 保留完整套件结构、挂接库并加载原厂配置 → 显示“在 ADS 元件列表中打开” → 打开原生 Palette 或 Component Library，定位该包的原厂分类 → 用户点击元件放入原理图并选择具体料号。Agent 同样通过该元件的真实 ADS 注册标识和真实参数进行放置。

保留“查看包清单”作为诊断动作，不能用展开文字、打开文件夹或另建聊天内列表冒充原生列表打开。必须分别解释 Palette 和 Component Library 的定位能力；若当前版本不支持某种程序化定位，说明已验证的限制，提供最接近的原生入口，不宣称已经选中分类。

本轮优先完成完整 Design Kit 路线。纯 Touchstone ZIP 单独识别，明确它通常没有原厂元件面板；包装元件作为后续独立阶段，不默认为完整原厂套件。

### 2. 先核实 ADS 2027 的真实加载机制

阅读本机 ADS SDK 源码、存根和官方文档，确认库打开时 `eesof_lib.cfg`、`BOOT_AEL`、编译 `.atf`、Palette、位图、Component Library 控制文件和数据搜索路径如何加载。验证现有 `ws.add_library` 是否已经触发完整加载，不预设必须手动执行 boot。

禁止编造 Design Kit、Palette 注册/刷新/打开 API；不要把编译 `.atf` 当文本执行，不要反复执行原厂启动入口造成重复分类。ADS 数据库和界面调用遵守已有主线程派发机制；解压和索引沿用后台任务。

从实际证据定位问题：区分未挂库、启动失败、元件未注册、Palette 缺失、图标缺失、界面未刷新、模型依赖缺失和版本不兼容。旧版套件兼容 ADS 2027 必须实测。

### 3. 在现有模块中扩展

- `backend/model_store.py`：补充套件配置、boot/palette、位图、浏览器控制文件等资源的检测及来源证据。静态检测存在不等于运行时加载成功。保留现有 ZIP 边界检查、资产隔离和原包完整性。
- `addon/ads_agent/model_ops.py`：复用挂接逻辑，补充运行时加载诊断、原生列表打开/定位、元件解析和必要放置能力；先确认已有工具能否满足，再决定增加工具名。元件数据从真实注册定义读取。
- `backend/model_orchestration.py`：扩展导入阶段与诊断结果，沿用工作区串行、取消、幂等及恢复机制。重开工作区后应可重新加载，不依赖本轮 Python 常驻变量。

### 4. 型号选择与仿真依赖

区分“原厂元件系列”和“具体料号”。例如一个 Palette 图标可能代表一个系列，具体料号通过原厂参数窗口选择。建立可追溯映射：package_id、库名、真实元件标识、系列、具体料号参数、实际值、模型依赖及来源。

参数默认值、可选料号和引脚定义优先读取原厂元件定义。读不到时标记未知，不能从文件名猜测。处理版本化库名和特殊字符，以实际 ADS 注册名称为准。

对 TDK 按原厂说明检查 Netlist Include 元件；对其他厂家按各自实际配置判断，不硬编码统一规则。静态识别说明文件与加载配置，结合实际生成网表确认 include、模型搜索路径、库/PDK/技术映射、子电路及必要偏置。补齐依赖应幂等，不能插入重复 include；未知依赖明确阻塞，不随机尝试语法。

验证模型真实引脚，禁止默认所有器件都是两脚。接地沿真实接地脚的出线方向紧靠放置，优先同轴短直连接；地符号与导线避开名称和 File 等文字，不改变电气网络。

### 5. 状态与证据

复用现有验证体系，追加或扩展以下证据维度：原包保存、解压、库挂接、启动配置加载、元件定义可解析、原生列表可见、指定元件可放置、依赖完整、仿真成功。列表检查拿不到证据时标记未验证，不能填成功。
