# 器件模型库实机验收报告（2026-10-19）

## 结论

在同一台机器的 ADS 2027（Python 3.14.6，64 位）中，用**两个互相隔离的新工作区**
完成了「模型库修订 → 导入 → 层次引脚 → 真实 symbol 视图 → 使用电路 → 网表
等价门禁 → 真实 hpeesofsim 仿真 → 读取真实 S 参数」的完整链路，两次结果
逐值一致。

仍未完成的是面板聊天入口的端到端（上传 PDF 的 UI → 聊天 → 工具）与
`validate_device_model` 的 published 判定；本报告不把这两项算作通过。

## 工作区 1：元件与 symbol

```
build_schematic(term_anchors)  → DeviceLib:J310CMP6:schematic
  10 实例（FET + 6 个 PKG R/L + 3 个层次端子）
  网表等价 ok，7 元件 0 差异；几何 0 问题
create_component_symbol       → DeviceLib:J310CMP6:symbol
  symbol_created=True
  读回引脚：1=s（1 个 pin 图形）、2=d（1）、3=g（1）；problems=[]
```

层次端子必须先建逻辑 Term 再补 pin 图形，否则 symbol 生成器因 `PinIter(term)`
为空而**只画图形、不生成引脚**。这一点在实机里复现过两次并已修正。

两个工作区的真实读数完全一致：

| 曲线 | 点数 | 最小值 (dB) | 最大值 (dB) | 100 MHz | 1 GHz |

可建图、可仿真且跨工作区可复现。

## 实机发现并修复的缺陷（都由真实执行暴露）

| # | 缺陷 | 影响 | 修复 |
| --- | --- | --- | --- |
| 1 | `add_numbered_term` 不创建 pin | symbol 生成器看不到引脚 → 生成的 symbol 没有引脚，无法放置连线 | 建 Term 后补 pin 图形 |
| 2 | `add_pin_fig_for_term_type("INPUT_OUTPUT")` | 抛 `TermType has no value` | 传枚举成员；最终改用 `add_dot_for_pin` |
| 3 | `add_pin_fig_for_term_type` 创建实例（I__7…） | 压在元件符号上，几何门禁把正常导线判为穿符号，重跑必失败 | 改 `add_dot_for_pin`（pin 图层点形状，不产生实例） |
| 4 | `PointF` 不可下标 | `getattr(loc,"x",loc[0])` 因默认参数立即求值而崩 | 分 x/y 与序列两分支 |
| 5 | `InstPin` 无 `term_number` | 引脚查找恒失败 | 复用 `_find_pin_on`（经 `inst_term.term_number`） |
| 6 | `_db_uu` 写成了 `db_uu` | NameError | 改为 `_db_uu()` |
| 7 | toolserver 热重载缺 `netlist_check` | 运行进程里新签名不生效，修复后仍报旧错 | 加入 `_ADS_OPS_DEPS` |
| 8 | 网表解析把 `define … end` 块内元件当顶层 | 顶层划分永远对不上 | 跳过子电路定义块 |
| 9 | 层次实例引脚数默认 2 | 三端元件少一脚 | 计划里显式 `_npins` |

这 9 项中 #1–#7 只有真机执行才会暴露 —— 也说明本轮之前「API 存在 + 单测通过」
并不等于元件可用。
