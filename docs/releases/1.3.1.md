# 1.3.1 — 安装完整性修复

日期：2026-11-03

这是一个**针对 v1.3.0 全新安装故障的修复版本**。如果你从 v1.3.0 的分发包
安装后所有工具都报 HTTP 500 / `KeyError: 'result'`，升级到本版即可解决。

## 修复

### 全新安装后所有工具失效（P0）

**症状**：从 v1.3.0 分发包全新安装后，任意工具调用都返回 HTTP 500，响应体
只有一行 `KeyError: 'result'`。连 `run_python` 只执行 `print("alive")` 也失败，
极易被误判为「ADS 主进程挂了」而去重启 ADS（重启无效）。

**根因**：`release_manifest.py` 的 `ADDON_FILES` 是分发链路的**唯一**白名单
（`tools/build_release.py` 按它打包、`install_addon.py` 按它部署），但漏登记了
`geometry_policy.py` 与 `schematic_rules.py`；而 `addon/ads_agent/ads_ops.py`
在模块顶层就 `import` 这两个模块。于是全新安装后 `import ads_ops` 直接抛
`ModuleNotFoundError`，`DISPATCH` 根本不存在，21 个工具无一幸免。

同一问题还波及 `appcad_chrome.py` / `appcad_circ.py` / `appcad_spec.py` /
`appcad_tl.py`：这四个模块由 `rfcalc_panel.py` 兜底导入，缺失不会炸工具服务，
但会让 **RF 计算器静默降级**（版式规格数据缺失，界面退化且不报错）。

**修复**：`ADDON_FILES` 补齐上述 6 个模块，现登记 26 个、与
`addon/ads_agent/` 下的实际模块数一致。

### 真实异常被吞成 KeyError（P1）

即使再次出现「漏登记」，也不应该让使用者看到一个毫无意义的 `KeyError`。
原 `toolserver.py` 的 `pump()` 里，`ads_ops = _get_ads_ops(...)` 自身抛异常时，
`except` 分支引用了未绑定的局部变量 `ads_ops`（`getattr(ads_ops, ...)`），
触发 `UnboundLocalError`，`ctx.fail()` 永远执行不到 —— 于是 `box` 里既没有
`error` 也没有 `result`，`submit()` 的 `box["result"]` 抛 `KeyError`。
附带副作用：该作业还会被 `finally` 记成 `succeeded`。

**修复**（`addon/ads_agent/toolserver.py`）：

- `try` 之前预绑定 `ads_ops = None`，异常处理器自身不会再炸；
- `ctx.fail()` 外面再包一层 `try/except BaseException`，`fail()` 自己失败时
  直接把错误写进 `box["error"]`；
- `submit()` 遇到「既无 error 又无 result」的空 box 时抛出带排查指引的
  `RuntimeError`，而不是 `KeyError`；
- `finally` 兜底：收尾时若仍无 result/error，补一条明确错误，
  作业也不会再被错记成 `succeeded`。

现在这类故障会直接显示 `ModuleNotFoundError: No module named 'geometry_policy'`
——真实原因一眼可见。

### 热重载依赖表漏项（P2）

`_ADS_OPS_DEPS` 补上 `geometry_policy` / `schematic_rules`。原先改这两个文件
不会触发 `ads_ops` 热重载，必须重启 ADS，与热重载机制的设计意图相反。

### 安装后自检（新增）

`install_addon.py` 部署完成后会执行 `verify_deployed()`：**以
`release_manifest.ADDON_FILES` 为权威**，检查

1. 清单登记的模块是否都已落地；
2. 磁盘上各模块的本地 `import` 是否都落在清单内（抓「加了模块忘了登记」）。

任一不满足就**当场中止安装**并报「安装自检未通过（程序文件不完整，插件将无法
使用）」，而不是等用户第一次调用工具时才炸。自检用静态 AST 分析，不 import
被测模块本身（`ads_ops` / `panel` 依赖 ADS 运行时，安装器跑在普通解释器里）。

## 测试

新增三条回归测试，均已用「还原旧代码 → 观察失败」的方式证伪：

- `tests/test_packaging.py::test_manifest_covers_every_addon_module_that_is_imported`
  —— 静态求 `__init__`/`panel`/`toolserver`/`ads_ops` 的导入闭包，断言清单
  覆盖全部可达模块、无幽灵条目、无遗漏；对旧清单会准确报出漏掉的 6 个模块。
- `tests/test_packaging.py::test_install_selfcheck_catches_incomplete_deploy`
  —— 自检对「缺文件」和「未登记」两种不完整都能抓到。
- `tests/test_toolserver_busy.py::test_ads_ops_import_failure_reports_real_cause_not_keyerror`
  与 `test_empty_box_becomes_explicit_error_not_keyerror` —— 对旧 `toolserver.py`
  精确复现 `KeyError: 'result'`，修复后返回真实异常。

## 升级说明

- **数据格式未变**（`DATA_VERSION` 仍为 1），无需迁移，直接覆盖安装即可。
- 已经手工把两个文件复制进安装目录的用户，升级到本版后由安装器统一管理。
- 注册文件与用户数据位置不变：
  `<ADS>\config\eesof_addons.xml`、`%LOCALAPPDATA%\ADSAgent`。
