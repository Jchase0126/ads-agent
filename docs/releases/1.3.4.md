# 1.3.4 — 旧后端自动重启 + 反馈默认开启

发布日期：2026-11-03

## 背景

用户反馈（v1.3.3 首次实机升级后）：设置页「检查更新」报
「后端版本过旧（缺少该接口），请关闭后端窗口后重新运行 start_backend.bat」。
原因：插件升级只替换了文件，**正在运行的后端进程还是升级前启动的旧代码**，
需要手动重启后端才能获得 /updates 接口。这个"升级后还要记得重启"的坑对普通
用户不够友好。

## 新增 / 修复

### 1. 后端过旧时主动提出自动重启（面板）

- `ConfigWorker` 对 404（缺少接口）的回执增加 `backend_old: true` 标记，
  与「后端未启动」（连接被拒）区分开。
- 面板在更新检查 / 准备更新收到该标记时，弹出**非阻塞确认框**：
  「自动重启后端 / 稍后再说」，每次面板会话只问一次。
- 重启流程（`_restart_backend_work`，后台线程，经 `_ReviveBridge` 回 UI 线程）：
  1. `GET /health` 确认 `service == "ads_agent_backend"`，取 `pid` 与
     `identity.install_id`，与本地 `install_state.json` 比对——**端口上不是
     本安装的后端时拒绝自动重启**，只提示手动处理；
  2. `taskkill /PID <pid> /F /T` 结束旧进程，轮询端口最多 15 秒等其松开；
  3. `cmd /c start "ADS Agent 后端" start_backend.bat`（新控制台窗口，工作目录
     为程序目录）重新拉起；
  4. 轮询 `/health` 最多 40 秒等健康检查通过；失败则把后端窗口里的线索
     显示到状态栏。
- 成功后自动重跑一次静默更新检查。

### 2. 崩溃反馈默认全开

`[feedback] auto_open_browser` 默认值 False → True（`backend/feedback.py`、
`addon/ads_agent/feedbackbridge.py`、panel 回退值、`config.example.ini` 同步）：
崩溃/卡死后不再弹三按钮询问框，直接打开预填 issue 页。三项开关
（启用诊断 / 自动打开浏览器 / 附带日志）仍可在设置页随时关闭。

## 已知边界

- 自动重启会中断进行中的对话与仿真任务，因此**必须经过确认**，不会静默执行。
- 若端口被另一份安装占用（install_id 不匹配），插件不会去杀别人的进程。
- 启动器脚本缺失或后端 40 秒内起不来时，回退为状态栏提示 + 手动指引。
