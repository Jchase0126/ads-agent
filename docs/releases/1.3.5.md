# 1.3.5 — 一键更新按钮 + 崩溃静默自动上传

发布日期：2026-11-03

## 背景

用户反馈两点（v1.3.3/v1.3.4 的更新与反馈功能基础上）：

1. 更新入口藏得太深——希望 GitHub 一发新版，面板顶栏就出现一个亮绿色按钮，
   点一下就自动完成更新并重启，不要翻设置页、不要手动跑安装器。
2. 崩溃上传要用户开浏览器、点 Submit 太麻烦——希望联网时默认自动上传，
   UI 里不再显示反馈表单。

## 一键更新（顶栏绿按钮）

- 检查到新版本（启动静默检查 + 每次打开设置页时检查）后，面板标题行出现
  「一键更新 v?」按钮（亮绿 #22C55E 圆角，objectName `updateTopBtn`）。
- 点击后自动串起整条链路：`POST /updates/prepare`（下载 + SHA-256 校验 +
  ZIP 有界预检）→ `POST /updates/apply`（校验暂存包 → 覆盖安装目录）→
  自动重启后端（核对 /health 身份后 taskkill + 拉起 start_backend.bat +
  健康轮询）→ 按钮消失。
- 下载/校验失败按钮恢复原样，状态栏显示原因；后端过旧（缺接口）仍走
  1.3.4 的「自动重启后端」确认流程。

## apply 的安全边界（新增）

- 与 prepare 共用单飞锁；只认本次 prepare 产出的暂存目录。
- 目标目录（安装目录）安全检查：含 `.git` 的开发检出**拒绝自动覆盖**；
  缺 install_addon.py 的目录拒绝。
- `_SKIP_NAMES = {"config.ini", "config.example.ini", "ads_toolserver.log"}`
  —— 用户配置与日志永不被更新覆盖。
- 覆盖前对只读文件 `chmod +S_IWUSR`；文件被占用（PermissionError）时返回
  明确错误提示「请关闭 ADS 与后端后重试」，不产生半套更新。
- 成功后读新包 `backend/paths.py` 的 `PLUGIN_VERSION` 回报 `applied_version`。

## 崩溃静默自动上传

- 上传通道：`POST https://api.github.com/repos/Jchase0126/ads-agent/issues`
  （Bearer PAT）。**无法匿名开 issue**，因此采用内置令牌：仓库源码里
  `EMBEDDED_UPLOAD_TOKEN = ""` 恒为空；打包时 `tools/build_release.py` 从
  gitignore 的 `tools/feedback_token.local` 读令牌注入 zip 内副本——凭据
  绝不进 git。
- 令牌三级来源：环境变量 `ADS_AGENT_FEEDBACK_TOKEN` > `config.ini [feedback]
  upload_token` > 包内内置令牌。都没有时 fail-closed：报告只存本机
  （`%LOCALAPPDATA%\ADSAgent\feedback\`），状态栏提示原因。
- 行为：`record()` 落盘后起守护线程后台上传；`snapshot()`（面板主动触发的
  路径）同步上传并把结果放进返回值；同一指纹 10 分钟内只传一次。
- UI 简化：设置页「崩溃反馈」整组控件移除，只留一行说明；崩溃时不再弹窗、
  不再开浏览器，只在状态栏显示「已自动上传诊断报告（issue 链接）」或
  「已保存在本机（指纹 …；自动上传未完成：原因）」。
- 菜单「报告问题 / 反馈崩溃…」保留：仍生成脱敏报告供手动查看/复制。

## 隐私口径（PRIVACY_NOTICE 同步更新）

- 上传内容：插件版本、系统/Python 环境、异常栈、**脱敏后**的最近日志、
  工具名。令牌/密钥、本机绝对路径、用户工程名/元件名、对话内容一律掩码。
- 联网时自动上传 + 本机留副本；失败不重试。
- `[feedback] enabled = false` 一刀切关闭（钩子、报告、上传全停）。

## 已知边界（诚实说明）

- **令牌公开风险**：zip 任何人可下载 → 内置令牌等同公开。该 PAT 仅授
  issues 写权限（最小权限），泄露影响 = 仓库出现垃圾 issue；作者可随时在
  GitHub 吊销重建 `tools/feedback_token.local` 重新打包。
- SHA-256 摘要证明的是「下载的字节 = GitHub release 挂的字节」，不构成对
  发布者身份的签名认证（发布链本身未改动）。
- C 层硬崩溃（access violation 直接杀死进程）写不出 Python 报告——这类
  只能靠 Windows 事件日志，本期不覆盖。
- 更新「应用」阶段在 ADS/后端运行时替换文件，个别被占用文件会走 PermissionError
  提示重试路径；按钮链路失败即回滚 UI 状态，已落盘的包可在下次重试。
