# 1.3.2 — 崩溃/卡死反馈

日期：2026-11-03

这个版本加了一套**故障反馈通道**：插件崩溃、卡死或工具报错时，可以一键生成
一份已脱敏的诊断报告，并打开预填好的 GitHub issue 页面供你提交。目标很单纯——
让「我这边出问题了」变成「开发者能定位的问题」，而不是一句"用不了"。

## 新增

### 崩溃/卡死反馈

- **一键生成报告**：面板「设置 → 崩溃反馈」里点「生成当前状态报告」，立即得到
  一份 Markdown 报告（同时复制到剪贴板），并打开已预填正文的 GitHub 新建 issue 页面。
- **崩溃自动捕获**：安装进程级异常钩子（`sys.excepthook` + `threading.excepthook`），
  主线程与后台线程的未捕获异常都会留档。
- **卡死看门狗**：面板每 30 秒写一次心跳文件，后端独立进程读取；超过
  `hang_seconds`（默认 180 秒）没更新即判定界面无响应并自动记录一份报告。
  用心跳文件而不是进程内计时，是因为真卡死时烧在 ADS 里的线程自己也不会跑。
- **弹窗与自动两种触发**（对应两种使用习惯，可随时在设置里改）：
  - 默认：故障后弹窗询问「打开 GitHub 填写 / 只保存到本机 / 忽略」。
  - 设置里勾选「崩溃后自动打开浏览器填写 issue」后：跳过询问，直接打开预填页
    （**会自动打开浏览器**，介意的话保持关闭即可），报告仍同时落盘。
- **报告只存本机 + 由你提交**：插件本身**不发送任何网络请求**，也不内置任何
  GitHub 凭据。它只生成文件、生成链接，最后一步的提交由你在浏览器里点。

### 隐私边界（写在设置页里，可见可查）

报告包含：插件/数据版本、操作系统与 Python 版本、异常栈、工具名、脱敏后的日志尾。

报告**不包含**：API 密钥与任何令牌、本机绝对路径与用户名、你的设计/工程/元件名、
对话内容、设计文件内容。

三道脱敏依次执行：令牌与 `key=value` → `<本机路径>` → 40 字符以上长串整体屏蔽，
另外调用方还会点名屏蔽当前设计名、Workspace 名。插件自身源码文件名会保留
（否则异常栈无法定位），用户的设计文件名不保留。

开关：`[feedback]` 段的 `enabled`（总开关）、`auto_open_browser`、
`include_logs`、`max_log_lines`、`hang_seconds`。关掉 `enabled` 后不生成报告、
不写心跳、不弹窗。

## 修复

- `release_manifest.py`：登记新增的 `feedback.py`（后端）与
  `feedbackbridge.py`（ADS 端），避免重演 v1.3.0 的「清单漏登记 → 全新安装
  整插件失效」。安装后的自检会核对这两个文件是否就位。

## 测试

- 新增 `tests/test_feedback.py`（核心：脱敏、指纹、去重、预填链接降级、心跳看门狗、
  钩子安装、隐私边界）、`tests/test_feedback_http.py`（HTTP 端点与鉴权）、
  `tests/test_feedback_panel.py`（设置项、objectName、心跳名一致性）。
- `test_heartbeat_name_matches_panel_bridge` 专门钉住「面板与后端心跳名必须一致」——
  两边漂移会让卡死检测**静默失效**（不报错、也永远检测不到）。

## 已知限制

- **C 层硬崩溃（访问违例/栈溢出）写不出 Python 报告**：那类崩溃进程直接消失，
  Python 钩子来不及跑。这类问题目前只能靠 `%LOCALAPPDATA%\ADSAgent\logs\` 下的
  日志排查。刻意没有接管 `faulthandler`——它只能输出到字符串，拼不出一份可信报告，
  塞进去反而会给出「已上报」的错觉。
- 报告不自动上传，因此没有服务端聚合视图；同一个 bug 的多次出现靠本机指纹计数
  （`reported.json`，窗口内重复不重复弹窗）。
