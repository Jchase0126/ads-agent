# 1.3.3 — 更新推送

日期：2026-11-03　上一个版本：1.3.2

## 新增

**软件更新推送**：GitHub 有新版本发布时，已安装的插件在联网前提下会收到更新通知，
用户点击「准备更新」即可下载最新安装包。

- 设置页新增「软件更新」分组：状态文案、启动自动检查开关（`[updates] auto_check`，
  默认开）、检查更新 / 准备更新 / 打开安装包所在文件夹三个按钮。
- 启动后 6 秒静默检查一次（不打扰、不弹窗）；有新版本只在状态栏提示一句，
  需要到设置页手动「准备更新」。
- 准备 = **下载 + SHA-256 校验 + 解压暂存**，绝不自动安装、绝不改动当前安装。
  准备完成后展示完整安装指引：保存工作 → 关闭全部 ADS 窗口与后端 →
  在资源管理器手动双击安装器（`install_addon.bat`）→ 重启 ADS。

## 安全设计（如实说明边界）

- 只信 `https://api.github.com/repos/Jchase0126/ads-agent/releases/latest` 的元数据
  与 GitHub 自动计算的 asset digest（`sha256:…`）；请求体里的任何 URL、路径、
  摘要一律忽略。
- 拒绝降级：latest ≤ 当前版本直接「已是最新」，不会重装旧包。
- 下载地址必须精确匹配本仓库 `releases/download/<tag>/ADSAgent-<版本>.zip`；
  重定向最多 4 次，且每跳都限定 github.com 系域名、禁用户凭据与非常规端口。
- ZIP 解压前逐条校验：单根目录 `ADSAgent-<版本>/`、拒绝 `..`/绝对路径/反斜杠/
  Windows 设备名/重复项/符号链接/加密条目；解压总量 ≤ 512 MB、文件数 ≤ 10000；
  必须包含安装器与后端/插件关键模块，缺一即拒。
- 中央目录在 ZipFile 解析**之前**先做有界预检（项数与目录大小超限即拒），
  防超大目录吃内存。
- `prepare()` 单飞：并发/重复请求直接返回「已在进行中」；下载有 600 秒总时限；
  暂存目录只保留最新一份，下次准备前自动清理。
- **诚实边界**：digest 校验证明「下载字节与 GitHub 上该资产一致」，不构成对发布者
  身份的签名认证；准备好的安装器在用户手动运行前存在同账户本机替换的理论窗口
  （SHA 只覆盖下载时刻）。安装器本身不是事务更新，失败可重跑，请先备份重要数据。
- CI/发布链未改动：发布仍走既有 `release.yml`（draft + 上传 zip + SHA256SUMS.txt）。
  注意：更新功能要求 release 附件带有 GitHub asset digest——通过 `gh release create`
  正常上传的资产都会带；若手工替换附件，请重新上传以刷新 digest。

## 已知限制

- C 层硬崩溃（原生段错误）写不出 Python 报告（Python 解释器已终止），只有日志尾部
  可用于事后定位。
- 更新检查/下载需要能直连 github.com；完全离线的机器收不到通知（属预期）。
- 「打开安装包所在文件夹」在 offscreen 测试中只验证了逻辑分支，真机（ADS 2022
  PySide2 / 2027 PySide6）首次点击建议人工确认能拉起资源管理器。
