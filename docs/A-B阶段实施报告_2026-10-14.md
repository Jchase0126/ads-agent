## A 阶段：仿真来源与模型状态

### A1 来源不再可自填

新增 `backend/sim_records.py` —— 可信仿真执行记录的唯一产地：

| 能力 | 说明 |
|---|---|
| `begin()` | 仿真**开始**时生成 32 位 hex `simulation_id` 并落盘 |
| `complete()` | 写数据集 SHA、网表指纹、三项完整性分账 |
| `resolve()` | 验证期逐项核对，返回 (证据, 问题列表) |
| `recheck_after_read()` | 数据集读取**之后**再校验一次 SHA |

落盘路径走 `paths.data_root()` → `<数据根>/sim_records/<id>.json`。

`backend/agent.py`：
- `_with_simulation_evidence` 现在**无条件丢弃**调用方的 `args["simulation"]`，
  只在会话缓存里有真实记录时注入 `simulation_id`。
- 新增 `_record_simulation()`：`run_simulation` 成功后落一条可信记录。

`backend/device_models.py`：
- `validate_device_model` 收到 `simulation` 参数**直接报错**；只接受 `simulation_id`。
- `simulation_id` **不再现造 `uuid4()`** —— 验证时生成再引用等于自己证明自己。

### A2 占位指纹与必填字段

`_dataset_provenance` 改走 `sim_records.resolve`，拒绝：
- 占位/非 hex 指纹：`invented` / `netlist_only` / `NOTHEX!!` / `-` / `n/a`；
- 必需字段缺失（workspace / library / cell / view / netlist_sha /
  dataset_sha256 / simulated_at）；
- library·cell·view·workspace 与建图记录**严格不等**（旧实现是「有值才比」）；
- 数据集 SHA 在读取前后各校验一次（防「读完换文件」仍关联旧模型）。

### A3 三项完整性分账 + 异常退出

`integrity = {process_exit, dataset_integrity, controller_trace}`。
本机已知的 `hpeesofsim` 退出码 `0xC0000409`（算完产出 .ds 后异常退出）被单独
标为 `abnormal_after_dataset`，记录 `diagnostic_only=True`：
产物可用于诊断，但**不计入端到端通过**。

### A4 状态机与独立网表验证

新增 `validation_mode="netlist_equivalent"`：独立网表正演只能得到
`numeric_spec_validated`，且 provenance **强制 unverified**。
原理图几何失败时不会整体置 validated。

`tools/acceptance_j310_ads.py` 原本自填 `netlist_sha="netlist_only"` 占位
（正是本次要禁的东西），已改为显式声明 netlist 模式。

### A5 参数集归属

`prepare_device_model` 新增 `_check_parameter_attribution()`：
参数集的 `document_id` 必须等于目标资料、`part_number` 必须等于目标型号
（跨型号需可核实的 `shared_range_quote` 同族声明）。

**归属检查放在曲线可用性检查之前** —— 否则跨手册参数集会被
「没有可用曲线」这条无关错误挡掉，归属缺陷被掩盖（这是我实测踩到的）。

## B 阶段：布局与走线规则统一

### B1 根因是实测出来的，不是猜的

新增 `tools/probe_symbol_bbox.py`：在 ADS 里逐个 `add_instance` 读真实 `inst.bbox`。
实测（ADS 2027，结果存 `output/acceptance_ab_20261014/symbol_bbox.json`）：

```
ads_rflib:FET      bbox=[0.0, -0.5, 0.575, 0.5]     ← 关键
ads_rflib:R        bbox=[0.0, -0.06875, 1.0, 0.06875]
ads_rflib:L        bbox=[0.0, -0.0375, 1.0, 0.0875]
ads_rflib:GROUND   bbox=[0.0, -0.125, 0.25, 0.125]
ads_simulation:TermG  bbox=[0.0, -0.1875, 0.875, 0.1875]
ads_simulation:S_Param bbox=[0.0, -0.46875, 2.575, 0.0]
```

`_AUTO_PIN_OFFS["FET"]` 的引脚只到 x=**0.5**，真实符号体到 x=**0.575** ——
**差 0.075**。规划期用 `_rough_box_public`（引脚包围盒），保存后复核用真实 bbox，
两套判据不同源。规划在 x=6.25（=5.7+0.55）画的竖线正落在这条差里：
**规划判合法，保存后判「穿过 DEVICE_CORE」**。

### B2 两处修复

1. **实测符号盒进入规划期避障**：`_SYMBOL_BBOX` + `_symbol_keepout()`
   （= 实测 bbox 按实例角度旋转 + `_SYMBOL_KEEPOUT_PAD` 余量），
   保证是真实符号体的**超集**。

2. **端点符号豁免改为按真实引脚判定**。旧规则是
   「端点落在 bbox 内 → **整段豁免**」，J310 那根线就是这样被放行的 ——
   它两端都不在 FET 任何引脚上（gate (5.7,0.5) / drain (6.2,1.0) /
   source (6.2,0.0)）。bbox 猜不出引脚位置，所以：
   - `boxes` 元素从 `(name, rect)` 改为 `(name, rect, pins)`；
   - 规划期 pin 由 `_pin_points()` 给（引脚档案 + 实例角度）；
   - 在线由 `_inst_pin_points()` 给（真实 `snap_point`）；
   - 没有 pin 信息时退回「端点必须压在符号体范围内」，不再整段放行。

3. **三端封装拓扑未破坏**：真实网表确认 g/s/d 三端都保留串联 R/L，
   公共端经 `R:PKG_R_G 0 N__16` → `L:PKG_L_G N__16 N__1` 接地，
   **内部公共端没有绕过封装支路直接接地**。

### B3 顺手修掉的既有缺陷

- `tools/acceptance_j310_ads.py` 的 `_parse_netlist` 用 `text.split()` 取
  `parts[1]`，但 ADS 网表 `FET:DEVICE_CORE N__1 ...` **冒号后无空格** ——
  实例名被读成节点号，导致六条 PKG 支路全部误判「缺失」
  （`fet_nodes=['N__2','N__3','G=15.5']`）。改用 `partition(" ")` 先切头。
- `tests/test_cb_amp_acceptance.py` **没有 `run()` 入口**，静默无输出、
  被 `run_tests.py` 当成通过。临时补入口后发现 5 项失败，且规划总长
  55.24 格 vs 文档基线 165.43 格 —— 说明该文件断言编码的是**旧版布局设计**，
  与当前 `auto_layout` 已脱节。属独立议题（需重新对基线或重设计 CB_FM_Amp
  布局），本轮**不**启用入口，只在文件内记录该发现，避免把无关欠账混进回归口径。
