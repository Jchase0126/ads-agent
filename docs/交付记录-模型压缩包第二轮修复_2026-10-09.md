## 二、本轮修复的 9 个真实缺陷

以下每一条都是**先复现、再定位根因、再修**，不是按审查报告机械改。
括号内是本轮的回归测试依据。

### 缺陷 1：工作区串行锁永不释放（致命）

- **位置**：`backend/model_orchestration.py` `_acquire_lock()` 及两个调用点
- **现象**：同一工作区**第一次导入成功，之后每一次都卡在 `waiting_lock` 永不执行**。
  用户视角是「第一次能导入，第二次永远转圈」。
- **根因**：`_acquire_lock` 拿到 `threading.Lock` 之后，全代码库**没有任何地方
  调用 `release()`**（`grep lock.release()` 只在取消分支出现）。所谓「串行」
  实际是死锁。
- **修复**：新增 `_release_lock()`，两个调用点（`run_sync` / `_worker`）一律
  包在 `finally` 里；用 `_held_locks` 记录持有者便于后续排查。
- **验证**：`test_history_is_bounded`（同工作区连续 6 次导入）从第 1 次就卡死
  变为 6 次全部 succeeded；`test_second_submit_joins_running_op` 通过。

### 缺陷 2：挂接工具名未登记，Design Kit 挂接 100% 失败（致命）

- **位置**：`backend/tools.py` `TIMEOUTS`
- **现象**：编排层派发 `attach_design_kit`，但后端白名单里没有这个名字，
  `tools.call` 直接抛 `未知工具: attach_design_kit`。
- **影响**：**所有 Design Kit 导入必然失败**，且报错信息完全误导
  （报「未知工具」而不是「工具未注册」）。
- **根因**：模型工具分两批加进代码，ADS 侧 `model_ops.HANDLERS` 与后端
  `TIMEOUTS` 没有对照过。
- **修复**：按 `model_ops.HANDLERS` 的真实注册名补齐 5 个工具
  （`attach_design_kit` / `detach_design_kit` / `list_readonly_libraries` /
  `list_library_components` / `inspect_component_model`）。
- **验证**：`test_model_import_flow.py` 从 **12 项失败降到 0**；其中
  `test_attach_workspace_mismatch_is_not_success`、
  `test_zero_attached_libraries_is_not_success`、`test_conflicts_wait_for_user`
  等 6 项原本全因这个缺陷失败。

### 缺陷 3：重启恢复作用在另一个 store 实例上（致命）

- **位置**：`backend/model_orchestration.py` `recover_interrupted_ops()`
- **现象**：后端重启后，未完成的导入**永远显示「进行中」**，界面不停转圈。
- **根因**：函数里 `store = _OpStore()` 新建了一个实例。恢复写的是磁盘文件，
  而查询接口读的是编排器内存里那份已加载的记录——两者分裂，磁盘上的
  `interrupted` 永远读不到。
- **修复**：改用 `get_orchestrator()._store`，与运行中的编排器共用同一份记录。
- **验证**：`test_restart_marks_ops_interrupted` 从失败（读到 `running`）
  变为通过（读到 `interrupted`）。

### 缺陷 4：排队阶段取消不更新资产状态

- **位置**：`backend/model_orchestration.py` `_acquire_lock()`
- **现象**：用户在排队时点取消，操作记录变成 cancelled，但**包本身永远停在
  `saved`**，界面上看不出这次导入被取消过。
- **修复**：加 `_cancel_while_queued()`，把包一并标为 `STATE_CANCELLED`。
- **验证**：`test_cancel_while_queued_never_runs`。

### 缺陷 5：LLM 并入按钮操作时拿不到「已并入」标记

- **位置**：`backend/model_tools.py` `_op_result_view()`
- **现象**：LLM 调用并入按钮已在跑的导入后，返回体里没有
  `joined_existing_op`，调用方无法区分「我发起的」和「我蹭了别人的」。
- **根因**：条件多判了 `op["source"] == "llm"`，而按钮发起的操作 source 是
  `http`，条件永远不成立。
- **修复**：只看 `op.get("joined")`。
- **验证**：`test_llm_tool_shares_the_same_op`。

### 缺陷 6：VAR 表达式只剥双引号

- **位置**：`addon/ads_agent/model_deps.py` `_unquote()`
- **现象**：网表里写 `MDIR + '/y.s2p'`（单引号）时，拼出的路径是
  `models'/y.s2p'`，文件明明存在却被判为 `relative_path_unresolved`，
  模型依赖状态降级为 incomplete，进而**触发不必要的重新仿真**。
- **修复**：双引号与单引号都剥（配对才剥，避免误伤）。
- **验证**：`test_var_expression_resolved`。

### 缺陷 7：工具端没有 model_deps 字段被当成「证据不足」

- **位置**：`backend/agent.py` `_reuse_recent_simulation()`
- **现象**：ADS 端较旧、返回体里根本没有 `model_deps` 字段时，
  `compare_model_evidence` 返回 `model_evidence_unavailable` → 拒绝复用 →
  **任何不引用外部模型的设计都会反复重新仿真**。纯浪费，且用户看不到原因。
- **根因**：把「工具端不具备这个能力」和「有能力但这次没解析成功」当成同一件事。
- **修复**：用 `"model_deps" in fp` 区分两者。能力缺失时退回网表指纹并**如实
  注明**；旧结果若本来带过模型证据，仍然保守重跑。
- **验证**：`test_reuse_kept_when_fingerprint_matches`（完整回归中发现）。

### 缺陷 8：优化记录缺轮次号

- **位置**：`backend/design_service.py` `run_optimization()`
- **现象**：日志输出「第 None 轮（L=1nH）达标项最多」——轮次编号丢失。
- **修复**：`record` 补 `"n": index`。
- **验证**：`test_optimization_is_bounded_and_records_best`，日志复核。

### 缺陷 9：`model_ops.py` 注释硬编码本机安装路径

- **位置**：`addon/ads_agent/model_ops.py` 顶部取证注释
- **现象**：注释里写着 `E:/ADS/Programfile/ADS2027/oalibs/...`，
  `tools/build_release.py` 的硬编码路径检查直接**拒绝打包**。
- **修复**：取证注释改写成 `$HPEESOF_DIR/oalibs/...` 相对写法（保留取证内容，
  不丢信息）。该检查存在的意义是防止代码依赖本机路径，注释同样不该带。
- **验证**：`tests/test_packaging.py` 8/8。

## 八、用户操作示例

以下是代码层面确认的接口用法（**未经实机验证**，实机跑通后需回来校正）。

### 8.1 上传原厂模型压缩包

面板聊天区拖入 ZIP，或点附件按钮。也可直接调接口：

```
POST /models/upload
Content-Type: application/zip
X-Ads-Filename: <原始文件名>
X-Ads-Session: <聊天项目 id>
Authorization / X-Ads-Token: <后端令牌>
```

上传只做**存档 + 只读扫描**，不解压、不执行包内任何脚本。

### 8.2 触发导入（附件按钮与 LLM 等价）

```
POST /models/import   {"package_id": "pkg_..."}
→ 202  {"op_id": "..."}          立即返回，后台执行
```

LLM 侧调用的是 `import_model_package`，内部走**同一条流水线、同一把工作区
串行锁、同一份操作记录**（`run_sync` → `_pipeline`）。若该工作区该包已有
进行中的导入，本次**并入**那条并返回同一个 `op_id`，不会重复挂接。

### 8.3 查询进度 / 取消

```
GET  /models/op?id=<op_id>
GET  /models/ops?limit=50
POST /models/cancel   {"op_id": "..."}
```

操作状态取值：`queued` / `running` / `awaiting_user` / `succeeded` /
`failed` / `cancel_requested` / `cancelled`（另有 `interrupted` 表示重启后
未完成、不默认视为已完成）。取消是协作式的，在下一个安全边界
（文件之间 / 数据块之间 / 阶段之间）停下，已完成的副作用保留。

### 8.4 查询与验证模型

```
LLM 工具：list_model_packages → list_vendor_models → get_vendor_model_info
          → validate_model_import（run_smoke_sim=true 才跑仿真）
```

**`import_model_package` 本身不会触发优化**——优化必须由用户明确要求
（`requested_by_user`），这是硬门禁。

### 通用问题与验收要求

- **挂库可见不等于网表可仿真。** 只检查 `lib.defs`、库名、cell 数量或模型定义可读，会漏掉真正运行时依赖。
