一、两个探测结论（写回 README 条目 6、7）

1. ADS 原生 Data Display 的 Python API —— 可用（端到端实证）。
   keysight.ads.dds 完整存在且有 Data Display Server 支撑，实测通过的最小链路：
   new_dds_file(path) → add_dataset_alias("wil9", <.ds 路径>) → new_page("R1")
   → page.add_plot(traces=["dB(S(2,1))","dB(S(3,1))"], title=...) → 
   plot.add_line_marker("m1", independent_value="5.9 GHz") → save(name=, path=) → close()。
   临时目录落盘 8401 字节 .dds 文件，之后已删除。
   注意点：save() 必须带 name（只传 path 会报 "No filename specified to save object"）；
   is_dds_app() 在 DE 进程里返回 False（DDS 是独立服务），不影响 API 使用。
   探针：tests/probes/Q_data_display_api.py、Q2_dds_deep.py、Q3_dds_sig.py、Q4_dds_e2e.py。
   结论：后续轮次可按上述实测名字实现"生成原生 .dds 曲线页面"。

2. 数据集横轴单位 —— 部分可用。
   keysight.ads.dataset 的 Variable/VariableBlock 上没有 unit/units 字段
   （公开成员仅 attrs/data_type/dtype/flags/is_indep/name/variable_type）。
   但 Variable.attrs 的标志串可读出轴类型，例如 freq 轴为
   "frequency type=real indep=yes mixop=neg"，S 参数为 "s-param type=complex"。
   结论：无量纲单位可读；R2 落地时可用 attrs 判定轴类型（frequency/time 等），
   量级推断（按声明频段落在数据范围内反推 Hz/GHz）保留为显式 fallback。
   现有推断 note 文案已在端到端验证中出现且表述准确（见三.1）。
   探针：tests/probes/R_dataset_units.py（骨架）、R2_units_live.py（实跑）。

二、五项风险验证结论（README「尚未验证的风险」1-5）

1. sim_off_main_thread 线程安全 —— 通过。
   方法：临时 cell AI_probe_sim（5G9 同构 + S 参数 60001 点），
   并行（sim_off_main_thread=true）与串行（=false）各跑一次 run_simulation，
   期间以 0.8s 间隔从另一进程发 run_python ping。
   结果：两种模式各 50000 点 S(2,1)（read_traces 降采样上限）逐点相对差为 0；
   并行期间主线程 ping 延迟 0.01-0.07s（ADS 保持响应）；串行期间 t+0.8s 的
   ping 延迟 1.54s（被主线程仿真阻塞，与面板"串行模式界面无响应"的描述一致）；
   /health 在两种模式下均全程 busy=run_simulation 且 elapsed_s 单调递增；
   当轮仿真窗口内 ads_toolserver.log 无 DE 相关异常。
   探针：tests/probes/T_sim_thread.py。

2. 令牌迁移收敛 —— 通过。
   方法：关闭两端，config.ini [ads] token 复位为 ads-agent-local-token，
   先启动后端再启动 ADS（完整重启一次）。
   结果：config.ini token 被轮换为随机值（DTGj****2DRc），后端日志打印脱敏指纹，
   check_env 显示"两端一致、无残留锁文件"；迁移后真实对话链路（SSE + LLM + 工具）
   完整可用。

3. 真实 SSE 链路下的多项目并行 —— 通过。
   方法：PySide6 offscreen 真实面板 + 真后端 8760 + 真实 DeepSeek
   （tests/probes/X_sse_multiproject.py）。项目 A 发长任务（驱动 run_simulation
   真工具链），A 在途时切到项目 B，B 视图为空；A 完成后回复完整写回 ProjA
   （assistant 正确汇总仿真结果与 S21 数值），随后 B 发短消息正常作答；
   双向零污染；projects.json 正确落盘（ProjA entries=3/history=2，
   ProjB entries=2/history=2）。

4. 真两进程同时写 config.ini —— 通过。
   方法：token 复位 legacy 后，在 ADS 进程内 ensure_backend() 自动拉起后端
   （此时后端读 legacy 令牌并轮换），同一窗口内另一进程连续 POST /config 10 次
   （等价面板「保存并应用」，tests/probes/Y_concurrent_config.py）。
   结果：10/10 返回 200；config.ini 七项检查全过——token 已轮换、[llm] model 有效、
   顶部注释/[agent]/[ui] 段与各键保留、configparser 可正常解析；
   check_env 报两端一致（XUro****FRJw）、无残留锁文件。

5. /health 长仿真忙碌状态 —— 通过。
   方法：AI_probe_sim 长仿真期间 0.4-0.5s 间隔采样 /health；
   再以 timeout=2s 发起同仿真触发超时（tests/probes/U_health_timeout.py）。
   结果：忙碌期间 busy 恒为 run_simulation、elapsed_s 单调递增、timed_out 全 False、
   结束后 busy=null；短超时路径返回 HTTP 504（"工具 run_simulation 在 2s 内未完成"），
   超时后 /health 继续报告该作业且 timed_out=True（2.0s-2.4s 采样可见），
   直到后台线程真正结束才清空。

四、验证过程中发现的问题（本轮不修，仅记录）

1. 【插件 bug，高优先级】run_python 脚本里 raise SystemExit 会令 toolserver
   主线程死锁。复现：probe_via_ads.py 跑任意含 raise SystemExit("...") 的脚本
   （本轮由 tests/probes/R_dataset_units.py 空跑触发）；现象：该请求挂起，
   此后所有 /execute 请求排队不返回，ADS 主窗口标题出现"未响应"，
   只能强杀 ADS 进程恢复。修复方向：run_python 执行器把 SystemExit 与
   BaseException 一并捕获转为错误返回。

2. 【插件 bug，中优先级】/design/reload 与 /design/run 的响应组装不一致：
   run 时结果页能拿到曲线，reload 后 job.to_dict() 的顶层无 traces 字段
   （画图数据在 artifacts.traces 里，前端按哪个键取需要统一；本轮程序化
   验证 artifacts.traces 数据完好，前端展示层是否取对键未验证——面板
   结果页如发现重载后无曲线，优先查这里）。复现：POST /design/reload
   {"job_id": "..."} 后对比 response.job 顶层与 artifacts.traces。

3. 【文档/健壮性】config.ini 原本没有 [agent] sim_off_main_thread 键，
   README 让用户"把 sim_off_main_thread 设为 false"时，手工加错段
   （如加到 [ui] 下两条重复键）会令 configparser 抛 DuplicateOptionError，
   ADS 端读 config 失败 → 所有请求 401（fail closed，行为安全但报错不直观）。
   本轮已把该键正式写入 config.ini [agent] 段（默认 true）。建议：
   配置读取失败时在 /health 与 401 响应里点名"config.ini 解析失败"。

4. 【环境现象】ADS 2027 每次启动弹 Product Selection license 对话框，
   不选择则 toolserver 不启动。自动化环境用 UIA 点 OK（等价人工确认）。
   对话框上有"Always try to start Advanced Design System with this selection"
   勾选项可绕过（本轮未勾选，保持用户环境原样）。

5. 【环境现象】Get Started 欢迎窗若在 toolserver 作业等待期间弹出并以模态
   方式运行，会阻塞主线程泵（表现为 /execute 挂起）；用 UIA Invoke 其
   Close 按钮即恢复。属 ADS 自身行为，面板侧无需处理，运维需知晓。

6. 【接口易错点】/design/run 的 band 需要数值+单位分开传
   （{"start": 2.3, "stop": 2.5, "unit": "GHz"}）；传 "2.3 GHz" 字符串
   会得到空 band，带内指标无法判定且不报错。建议 build_spec 对无法解析的
   band 显式报错（本轮未修）。

7. 【环境现象】ADS 单实例机制：已有 hpeesofde 时再次启动 ads.exe 不会开
   第二实例；强杀 hpeesofde 后偶发僵尸 LISTENING socket 占住旧端口
   （本机 8761 曾被占死）。规避：改 config.ini [ads] port（本轮 8761→8762）。
   顺带修正 tests/probe_via_ads.py 硬编码 8761 → 从 config 读取。

8. 【观察项，行为符合设计】read_traces 默认 max_points=50000，60001 点
   仿真结果被降采样并标记 truncated（两次同参数对比不受影响，因为都做
   同样降采样）；design_jobs 只存 display 序列与 .ds 引用，不存完整数组。
