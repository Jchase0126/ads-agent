## 3. 冻结接口

### 3.1 ADS 侧新工具（唯一新工具名）

**工具名：`open_vendor_palette`**（注册进 `model_ops.HANDLERS` + `backend/tools.py::TIMEOUTS`≥240 +
`backend/model_tools.py::ADS_HANDLERS` + `backend/tools.py::TOOLS` schema）

入参（`workspace`/`kit_root` 由**后端可信上下文**解析注入，绝不接受 LLM 给的路径）：

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `package_id` | str | 是 | 后端用它解析可信 kit_root |
| `workspace` | str | 是 | 后端注入；与 ADS 当前工作区不符→`workspace_mismatch` |
| `kit_root` | str | 否 | 后端注入（绝对路径）；缺省时由 ADS 侧从已挂接库回推 |
| `library` | str | 否 | 目标库名；缺省取该包第一个已挂接库 |
| `category` | str | 否 | 期望定位的 palette 分类/组名 |
| `view` | str | 否 | `"schematic"`(默认) / `"layout"` |
| `focus` | bool | 否 | 是否把库浏览器窗口置前，默认 True |

返回结构（**键名冻结**，新增键只能加不能改名）：

```jsonc
{
  "ok": true,
  "outcome": "opened|loaded_only|not_attached|unsupported|workspace_mismatch|failed",
  "workspace": "...", "package_id": "...", "kit_root": "...", "library": "...",
  "library_attached": true,
  "boot": {
    "eesof_lib_cfg": {"path": "", "exists": false},
    "boot_ael": {"path": "", "exists": false, "atf_path": "", "atf_exists": false},
    "loaded": true,                       // true|false|"unknown"，不许猜
    "registered_components": 0,           // 能 dm_find_item_definition 命中的 cell 数
    "palette_groups": [ {"library":"","window":"schematic|layout","design_type":"",
                         "name":"","label":"","items":0,
                         "owner":"boot|probe|sdk","source":""} ],
    "control_files": {"lib_browser_ctl": {"path":"","exists":false}, "records": []},
    "evidence": ["..."]
  },
  "native": {
    "component_library": {"opened": false, "method": "", "detail": ""},
    "palette":           {"opened": false, "method": "", "detail": ""},
    "located": {"library":"","category":"","found":false,
                "via":"deitem_get_visible_palette_name","window":""}
  },
  "palette_api": {"create_schematic_palette": true, "create_layout_palette": true},
  "limits": ["本机 ADS 2027 未提供程序化打开 Palette / Component Library 窗口的 API（仅可定位已注册分组）"],
  "verified": false,
  "record_path": "",
  "steps": [ {"step": "", "ok": true, "detail": ""} ],
  "error": ""            // 失败时给可读原因
}
```

`outcome` 语义（2026-10-09 依实机探测修订）：
- `opened` = 把**已存在**的原生窗口（`find_windows_by_type(BROWSER_WINDOW)`）成功置前 **且** 定位到库/分类；
- **`located` = 已在原生列表注册并定位到库/分类，但无法程序化打开窗口** —— TDK 这类正常包的**主路径**；
- `loaded_only` = 库已加载，但既未定位到分类、也未打开窗口；
- `not_attached` = 库未挂接；`unsupported` = 非 Design Kit（纯 Touchstone）；`workspace_mismatch`；`failed`。

**`boot.loaded` 的判据（必须用确定性探测，官方无文档但实测可用）**：
`dm_find_item_definition("<lib>:<firstCell>")` 非空，或 `deitem_get_visible_palette_name(win, lib, cell)` 非 `None` → `true`；
两者都明确为空 → `false`；探测本身不可用（API 缺失/无窗口）→ `"unknown"`。
**禁止**用 boot.ael 的全局 decl（如 `TDK_DK_PATH`）当加载判据 —— 实测它在 default vocabulary 中不存在，但 item/palette 已注册。

### 3.4 静态检测（model_store）

`scan_archive` 结果新增同级键 **`native_list`**：

```jsonc
"native_list": {
  "eesof_lib_cfg": ["相对路径"], "boot_ael": [], "palette_ael": [], "atf": [],
  // boot_ael：BOOT_AEL 值不带扩展名，按 原样→.ael→.atf 探测，命中即登记。
  // palette_ael：**含 .ael 与 .atf 编译产物**（.ael 排前）。
  //   ⚠ 真实 TDK 包只 ship `de/ael/palette.atf`（全包 .ael 数为 0）——
  //     只匹配 .ael 会漏掉 palette 资产；2026-10-09 已修为双扩展名（独立验证发现）。
  "bitmaps": ["目录"], "browser_ctl": [], "lib_defs": [], "data_paths": [],
  "design_kit_name": "", "version": "", "tech_desc": "",
  "has_palette_assets": false,
  "evidence": ["..."], "limits": ["静态存在≠运行时加载成功"]
}
```

**路径基准（store-eng 落定，2026-10-09）**：cfg 内的值（`BOOT_AEL`/`LIB_BROWSER_CTL`/`INPUT_DATA_PATH`/`TEMPLATES_DIRECTORY`）
在**解析时**相对 `eesof_lib.cfg` 所在目录；但**返回/落库的路径是「包根相对」posix 路径**，
与既有 `plan` / `lib_defs_paths` / `atf` 同口径 —— 调用方 `join(extract_root, path)` 即可定位。
`BOOT_AEL` 无扩展名时按 `值原样 → .ael → .atf` 依次查找，**命中即登记**（DemoKit 两者都有，TDK 只有 `.atf`）。
指向包外（`$VAR`/`%VAR%`/绝对路径）或越出包根的段一律记入 `limits` 并留空，**不许猜**。
各列表上限 100，超限在 `limits` 说明。
