## 2 目标状态机（唯一权威）

记 `V` = 本地当前版本（`pathbridge.load().PLUGIN_VERSION`，去掉可能的 `v` 前缀；取不到则空）。

| 状态 | 可见 | 文案 | tooltip 必须含 | 可点 |
|---|---|---|---|---|
| 初始（未检查） | **是** | `v{V}`；`V` 为空 → `检查更新` | `当前版本 v{V}` + `点击检查更新` | 是 |
| checking（非静默） | 是 | 不变（仍是 `v{V}`，**不许闪成"正在下载"**） | 同上 + `正在检查` | 是 |
| update_available | 是 | `一键更新 v{latest}` | `有新版本 v{latest}` + `点击后自动下载、校验并更新` | 是 |
| up_to_date | 是 | `v{current}`（**数据里的 current_version 优先**，为空才用本地 `V`） | `已是最新版本` | 是 |
| error / 离线 | 是 | `v{V}`；`V` 为空 → `检查更新` | `检查更新失败` + 原因摘要（可截断） | 是 |
| preparing（下载中） | 是，**禁用** | `正在下载更新…`（沿用现文案） | 不变或补 `正在下载` | 否 |
| applied（更新完成） | 是 | `v{applied_version}` | `已更新到 v{...}` | 是 |
| prepare 失败后复位 | 是 | 回到 `v{V}`（**不是** `一键更新`） | 补 `上次更新失败` | 是 |

补充规则：
1. **绝不因"没有新版本"而隐藏按钮**；本波之后按钮只在面板销毁时消失。
2. 点击分流（新增 `_on_top_update_clicked()`）：
   - 最近一次检查结果为 `update_available` → 调 `_apply_update_now()`（保持现有一键链路）；
   - 其它状态（初始/up_to_date/error）→ 调 `_check_updates(silent=False)` 重新检查；
   - `preparing` 期间不响应（按钮已禁用）。
   - 判断"最近一次是否可用"用面板上的状态标记（如 `self._update_latest_available = latest`），不要重新请求。
3. 样式：**不改颜色/尺寸/圆角/位置**（继续用 :2079-2084 的绿色 stylesheet），只改文案/可见性/可点性。
4. 所有新逻辑 **never-raise**（面板既有风格）：`try/except BaseException`，失败时保持上一次文案。
5. `setAccessibleName` 同步更新为当前语义（如 "当前版本 v1.3.5，点击检查更新"），避免读屏用户听到"发现新版本"。
6. 状态栏 `self.status` 的既有文案（:2599 发现新版本提示、:2675 已更新提示）**不动**。

## 3 版本号取用纪律

- 本地版本一律走 `pathbridge.load()` 的 `PLUGIN_VERSION`，用 `getattr(..., "PLUGIN_VERSION", "")`；
  `pathbridge` import 失败或返回空 → 视为 `V=""`（走 `检查更新` 兜底），**不得** hardcode "1.3.5"。
- 数据里的 `current_version` / `applied_version` 优先于本地常量（后端是权威），但只用于**显示**，不回写任何配置。
- 文案统一 `v` + 版本号；版本号本身若已带 `v` 前缀，不重复加（`v1.3.5` 不写成 `vv1.3.5`）。

### 4.2 必须新增的用例（写在 `tests/test_update_ui.py`，A 负责）
1. 初始状态：按钮可见、文案以 `v` 开头、tooltip 含 `当前版本` 与 `点击检查更新`。
2. `up_to_date`：文案取数据 `current_version`（`1.4.0`），而不是本地 `1.3.5`（构造本地≠数据的场景）。
3. `update_available`：文案 `一键更新 v1.4.0`，点击**触发 prepare 链路**（patch `_prepare_update` 计数）。
4. `up_to_date` 时点击：**触发重新检查**（patch `_check_updates` 计数），**不触发** prepare。
5. `error` 状态：文案仍是 `v{V}`、按钮可点、点击触发重新检查。
6. `V` 取不到（patch `pathbridge.load` 抛异常/返回空）：文案 `检查更新`，且**never-raise**。
7. `applied`：文案变成 `v{applied_version}`。
8. 垃圾数据（`_on_update_checked({})`、`{"status": 123}`、`None`）：never-raise，按钮仍可见且文案非空。

2. **§2 补充一条未预见的分支**：`backend/update_service.py:346 _prepare_locked()` 在 `:350` 会重新 `_check()`，若 `:351-352` 判定 `status != "update_available"` 直接返回，而 `_check` 可返回 `up_to_date`(:142) —— 即"用户看到「一键更新 v1.4.0」点下去，后端复检说其实已是最新"是真实可达路径。实现必须在该分支复位：清 `_update_apply_requested` / `_update_latest_available`、置 `_update_top_state="up_to_date"`、`current_version` 非空则写、`_show_top_update("")`、`setEnabled(True)`；**不得**用 `_restore_top_update_btn()`（它的 tooltip 写"上次更新失败"，与"复检为最新"不符）。已由 A 在 `panel.py:2913-2924` 实现，B 的第 12 条用例覆盖。
