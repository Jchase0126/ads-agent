## 优先修复问题

### P1：导入请求的 HTTP 响应生命周期错误

位置：backend/server.py，`_handle_models` 的 POST /models/import 分支。

主线程启动后台线程后发送 accepted 响应，并关闭该连接；后台线程完成或失败后再次调用同一个 Handler 的 `_send_json`。因此一个请求存在两次响应及并发写 socket 的可能，后台完成消息可能写入已关闭的连接。现有 model_http 测试没有覆盖 import/cancel 请求。

建议：接收时只返回一次 202 和 op_id；后台线程仅更新操作记录、包清单与错误；通过独立操作状态接口查询最终结果。先固定工作区再注册操作，将锁等待和取消状态也写入记录。

### P1：ADS 返回挂接失败，编排层仍记录成功

位置：backend/model_tools.py，`import_model_package` 调用 attach_design_kit 后。

`tools.call` 会原样返回 JSON，其中 ok=False 不一定抛异常。编排层只捕获异常，没有检查 attach.ok、cancelled、conflicts、failed，就继续记录 attach 步骤成功并进入 pending_verify。

本次用临时 ZIP 和替身实际复现：ADS 返回 `ok=False, kind=workspace_mismatch`；后端仍返回 `state=pending_verify`，最后步骤为 `attach, ok=True, detail=0 个库`。

建议：明确检查业务结果；失败、冲突、部分挂接和取消分别处理，保留实际完成的副作用。不能在失败信息中无条件声称未修改库定义。

### P1：基础仿真没有形成有效测试电路

位置：addon/ads_agent/model_ops.py，`_smoke_sim`。

当前仅添加 X1、两个 TermG 和 S_Param，没有连线或绑定引脚网络，也没有为两个端口分别指定编号。代码随后直接生成网表并调用 `_simulate`，未复用正常仿真的连通性门禁。固定两个端口也不能覆盖任意端口数量、三极管偏置及多端口器件。

此外，调用 `_close_design` 后又尝试 save_design；仿真阶段直接同步调用 `_simulate`，可能在 Qt 主线程上阻塞面板。

建议：按元件端口定义构造测试夹具，明确端口编号、接地和必要偏置；保存后只读复核，执行连通性与网表门禁；沿用现有后台仿真机制。先证明两端口 Touchstone 的最小链路，再扩展器件类型。

### P1：模型指纹没有接入正常仿真结果

位置：addon/ads_agent/ads_ops.py 的 run_simulation、_simulate、design_fingerprint；backend/agent.py 的 `_last_sim` 和 `_reuse_recent_simulation` 对应逻辑。

新增指纹只有调用 design_fingerprint 且 include_models=True 时计算。正常 run_simulation/_simulate 没有产出 model_fingerprint；Agent 和 design_service 仅尝试消费该字段，导致通常记录空值。缓存检查又以旧值非空为前提，因此同一路径模型文件内容变化的保护通常不会执行。

指纹扫描只看顶层实例的直接文件参数，后缀仅覆盖 .s1p–.s4p、.snp、.ts；不解析工作区相对路径、VAR 表达式及层次化 Design Kit 依赖。

建议：在生成用于仿真的网表时同步记录实际依赖与内容指纹，并将证据随结果持久化；区分“没有模型依赖”和“无法解析依赖”。无法确认时不复用。补充同路径内容替换、相对路径、多端口文件及层次模型的回归。

### P1：Touchstone 验证及就绪状态存在缺口

位置：backend/model_tools.py 的 validate_model_import，addon/ads_agent/model_ops.py 的 validate_model_import。

验证接口只接受 library/cell，没有 package_id/model_id。回写包状态仅靠挂接库名匹配；普通 Touchstone 包不挂接库，因此即便验证内置 S 参数元件，也不能把对应文件包的状态更新为 ready。

另一方面，Design Kit 中一个元件静态校验通过即可把整个包标为 ready；无 model_def 或要求冒烟仿真但实际未运行时，也可能只产生 warnings/unverified，最终仍 ok=True。

建议：以具体模型文件、元件和参数组合记录验证；区分“文件已解压”“静态可解析”“已仿真验证”，保留各自证据。取消或未完成要求的仿真不得标为仿真就绪；包级状态不得暗示包内所有模型均验证通过。

### P2：附件动作没有固定原始工作区

位置：addon/ads_agent/panel.py 的 `_attach_import`、`_on_packages`、`_verify_attachments`；backend/server.py 的模型接口。

卡片记录了 workspace，但导入请求只发送 package_id，后端重新取当前 Workspace。轮询也取当前工作区的包列表；同一 package_id 在不同聊天中出现时，`_find_attachment` 只返回第一张卡片。

建议：操作标识绑定上传时的 workspace 和 package_id；用户切换工程后明确拒绝不匹配的操作。卡片引用定位要包含聊天项目与资产工作区，更新同资产的所有引用或明确更新目标卡片。

### P2：取消与串行导入不统一

位置：backend/server.py、backend/model_tools.py、backend/model_store.py。

HTTP 导入入口有工作区锁，LLM 工具入口直接调用编排函数，不经过这把锁。取消只在解压前和挂接前检查，extract_package/index_models 未接收取消事件；Touchstone 分支没有索引完成后的取消检查。后台任务状态与 cancel 回执没有统一持久化。

建议：把导入锁和操作状态放到共用编排层；在文件和块边界检查取消；将 ADS job_id 纳入取消传播。已完成步骤与已停止步骤应分别展示。

### P2：频段与偏置目前只是提示

已解析频率范围、参考阻抗和偏置变体，并向 LLM 提供说明，但 design_service/design_metrics 没有模型覆盖门禁。ADS 对超出模型频率范围的数据插值或外推后，仍可能得到看似达标的曲线。

建议：以实际选中的模型变体核对目标频段和条件；覆盖不足时将指标置为未知或拒绝自动达标结论。型号离散选型需要明确候选集、迭代上限和最佳已验证结果。
