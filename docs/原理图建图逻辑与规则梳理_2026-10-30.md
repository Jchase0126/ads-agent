## 0. 一句话结构

画图这件事被拆成四个互不共享实现的层：

| 层 | 决定什么 | 实现位置 | 判定失败后果 |
|---|---|---|---|
| 布局层 | 每个实例的 x/y/angle/annot | `addon/ads_agent/ads_ops.py:2611-5021` `auto_layout_positions` | 退化摆放（不报错） |
| 走线规划层 | 每条连接走哪些折点 | `addon/ads_agent/ads_ops.py:5046-5414` `plan_wire_routes` | 降级为逐条在线寻路（`fallback_reason`） |
| 绘制/校验层 | 实际 `add_wire` 的合法性 | `_route_clear` / `_route_around` / `_wire_connection`（`:1242-1488`） | 抛 `RuntimeError`，本图不落盘 |
| 复核层 | 落盘后几何/电气是否符合规则 | `_geometry_report`（`:1638-2063`）、`_design_audit`（`:385-502`）、`_netlist_gate`（`:5738`） | 抛 `RuntimeError`，但图已落盘 |

关键一点：**规划层和复核层不是同一个函数，也不是同一份符号盒**。规划用静态引脚档案 `_AUTO_PIN_OFFS`（`:2326`）加实测 bbox `_symbol_keepout`（`:5417-5446`，优先 `_SYMBOL_BBOX` 旋转 + `_SYMBOL_KEEPOUT_PAD=0.05` 外扩，未实测退回 `_rough_box_public` `:5448` 的引脚包围盒）；复核用磁盘上的 `inst.bbox`（`:986-1003`）。历史上"规划判合法、保存后报穿过符号"就是这条缝（`docs/A-B阶段实施报告_2026-10-14.md:108-111` 记录了 FET 档案 x=0.5 vs 真实体 x=0.575）。

## 1. 入口与坐标策略

工具入口只有 `build_schematic`（`backend/tools.py:176-273`，实现 `addon/ads_agent/ads_ops.py:5780-6127`）。`addon/ads_agent/toolserver.py` 只做 HTTP 分发与 `run_python` 常驻环境，不含任何 schema 文本。

`layout` 缺省时按下面的矩阵推断（`ads_ops.py:5794-5805`）：

| 请求形态 | 推断结果 | 走哪段代码 |
|---|---|---|
| 有 instances，全都没写 x/y | `auto` | `:5818-5879` 自动布局 + 走线规划 |
| 有 instances，任一写了 x 或 y | `explicit` | `:5881-5886` 强制校验每个实例 x/y 齐全 |
| 只给 `var`，没有 instances | `explicit` | 直接放 VAR |

这么设计的原因写在 `:5795-5801`：部分坐标 + auto 混用会覆盖手工位置，所以宁可判成 explicit 让调用方补全。

`auto` 有一条硬边界：**只支持空设计或 `recreate=True`**。

```python
if layout_mode in ("auto", "flow") and n_before > 0 and not recreate:
    raise RuntimeError(...)   # ads_ops.py:5952-5956
```

代码理由（`:5949-5951` 注释）：规划阶段看不到设计里已有的实例，增量追加会把新元件排到旧元件上。

`"flow"` 是 `auto` 的别名（`:5818`、`:5952`、`:6105`），但 schema 枚举里只有 `["auto","explicit"]`（`backend/tools.py:218-221`）。

## 2. auto 布局规则

`auto_layout_positions(instances, connections, var_spec=None)`（`:2611-5021`）。输入输出都不改电气，只产坐标；坐标 `round(…,4)`，**不吸附网格**（`GRID_STEP=0.25` 只存在于 `geometry_policy.py:75`，`ads_ops.py` 零引用）。

### 2.1 角色分类

`master` 先经 `_master_short` 归一化（`ads_rflib:MLIN` → `MLIN`，`:2428-2435`），再分三类（`:2643-2649`）：

- `gnd`：`GROUND` / `GND`（`_AUTO_GND_MASTERS`，`:2311`）
- `annot`：`VAR`/`MSUB`/`S_PARAM`/`SWEEP_PLAN`/`OUTPUT_PLAN`/`OPTIM`/`GOAL`/`EQN`/`NOTE`/`TEXT`/`NODESET`/`STIM`… 或命中 include 正则（`:2313-2320`）
- `rf`：其余，只有 `rf` 参与信号布局（`:2651`）

### 2.2 主干

端口集合 `_AUTO_PORT_MASTERS = {"TERM","TERMG"}`（`:2312`），按名字排序（`:2970`）。主干不是 BFS 也不是 Dijkstra，而是**枚举每对端口之间的全部简单路径**，再按 `(路径长度, 端口名对, 路径字典序)` 排序取第一条（`:2972-2986`）：

```python
cand.sort(key=lambda c: (c[0], c[1], c[2]))
main = cand[0][2]
```

副作用：端口改名会改变主干选择，复现性依赖实例命名。端口多时是指数级（作者在 `:2639-2642` 承认 ≥50 级要 0.4~1.9 s）。

搜索图是 `adj_side`——只收"两端都不是分支脚"的边（`:2777-2785`）。分支脚靠叉积判（`:2719-2722`）：

```python
ax = _rot_off(p2[0]-p1[0], p2[1]-p1[1], _angle_of(n))   # 通轴向量
if abs(ax[0]*ry - ax[1]*rx) > 1e-9:                      # 该脚偏离通轴
    labels.add(label)                                    # → 分支脚
```

轴标签默认 `("1","2")`，例外 `_AUTO_AXIS_LABELS = {"CLIN": ("1","4")}`（`:2388`，因为 CLIN 的 1→2 是耦合边、直通边是 1→4）。没这条规则，隔离电阻（两端都是分支脚）会被误认成端口路径的一段，把 λ/4 支线挤成桥接件（Wilkinson_5G9 实测）。

无端口或端口间不通时落 `_fallback_chain`（`:2552-2564`，全图最长简单链），保证布局总能给出结果。

### 2.3 对称分支

`_match_sym_split`（`:2988-3033`）识别一分二/三/四：要求两臂首件不同、同尾、前缀长度 ≥1、分叉件该脚是真 T 结、臂数 2~5。臂数 `k` 只在 2/3/4 有 `_sym_rows`，k=5 直接 `raise`（`:3040-3050`）。

对称段内 4 个明确失败出口（`"桥跨中间臂"`、`"行距放不下竖放桥接件"`、`"两臂桥接引脚不同列"`、`"对称布局盖不全"`，`:3137-3177`）中任意一个抛出，都被整体 `except` 兜住并**清空所有已摆件**回退通用布局（`:3215-3220`）——那段计算全白做，但不影响最终结果。

### 2.4 分支臂

流程（`:3222-4327`）：从未放端口/元件出发，沿 `adj_all`（全边，含分支脚边）BFS，第一次触达已放元件即锚点（`:4238-4251`）。三处主动跳过：

- `n_ext >= 2`（跨链桥接件）→ 跳过，留给桥接阶段（`:4261-4263`）
- 非分支脚引入且锚点引脚不是真 T 结 → 跳过（`:4264-4268`），`_junction` 判据是节点大小 ≥3（`:2792-2794`）
- 自由脚对端未放齐 → 第一轮推迟到第二轮（`:4284-4286`），第二轮不再推迟（否则环形拓扑死锁）

行号分配（`:4287-4289`）：

```python
row = row_of.get(anchor, 0) + 1
branch_no[anchor] = branch_no.get(anchor, 0) + 1
row += branch_no[anchor] - 1        # 同锚点多条分支依次再下移
```

行 y 是**动态累计**，不是固定步长（`:3344-3345`）：

```python
y = _row_y(r-1) - max(_ROW_GAP_MIN, _row_depth(r-1) + _ROW_GAP_MARGIN)   # 2.6 / 0.25
```

`_row_depth` 取该行已放件的符号粗略盒、文字区下探深度，带地脚的件再加 `pin_low + 0.8`（`:3316-3337`）。docstring `:2624-2625` 里"行距 5"是**废弃的旧规则**，代码已无该常量（`:2402-2404` 注释自陈"不再固定 5.0"）。

后验占位检查：摆了就和已放件做粗略盒相交测试，撞了整链下移一行重摆，`row >= 12` 后停止并**接受碰撞**（`:4296-4323`）。

### 2.5 间距常数

`:2386-2411`：

| 常量 | 值 | 含义 |
|---|---|---|
| `_CHAIN_GAP_MIN` | 1.4 | 链内相邻引脚间距基线 |
| `_GAP_TEXT_MARGIN` | 0.5 | 前件文字伸出量之外的余量 |
| `_CHAIN_GAP_TALL` | 1.9 | 任一侧为高文字块（MTEE 5~6 行）时的间距下限 |
| `_ROW_GAP_MIN` | 2.6 | 分支行距下限 |
| `_ROW_GAP_MARGIN` | 0.25 | 行距相对上一行深度的余量 |
| `_SYM_ROW_H` | 3.0 | 对称臂行距 `d` |
| `_SYM_GAP` | 1.4 | 对称臂链内间距 |

逐对间距（`:2923-2941`）：取 `max(g, 前件文字伸出 + 0.5, 高文字块下限)`，前件出脚为竖直脚时再额外让 1.0。

### 2.6 跨链桥接件

两端都是分支脚的件（隔离电阻）只进 `adj_all`，永不进 `adj_side`，不进主干也不进分支尾，最终落到桥接循环（`:4331-4586`）：

- 串链要求候选唯一（`len(nxts)!=1 → break`，`:4339-4346`）
- 无已放邻居 → 兜底 `(0.0, _row_y(1))`、行 1
- 骑上下两行正中：`mid_y = (_row_y(up_row) + _row_y(lo_row)) / 2.0`（`:4357`）
- 同行双锚（闭环环拓扑）：走"人行道" `lane_y = _row_y(up_row) - 1.4`，整链居中于两锚点（`:4358-4376`）
- 竖放单件（`len(chain)==1 and angle%180==90`，Riso 典型形态）：`_bx_y = mid_y - 0.5`（`:4409`），x 候选 `[中点, up.x, lower.x]` 加 `0.25/0.75/0.4/0.6/0.15/0.85` 比例点，用 `_bridge_x_clear` 检查符号盒 + 文字区 + 两段 L 走线横段有没有穿字（`:4417-4469`）
- 横放/多件桥：x 候选用罚分函数取最小——文字互压 `+1`、撞盒 `+1`、横段穿字 `+2`、横段总长 `*0.001`（`:4505-4559`）

### 2.7 GROUND 就近

前置：`build_schematic` 在 auto 分支先调 `_localize_shared_grounds`（`:5823`，定义 `:2567-2606`），把共享地符号按被接地引脚拆成 `GND_local2`、`GND_local3`…（`:2592-2606`）。理由：ADS `GROUND` 是全局 net 0，一个共享符号会把远端回流支路拉成整张图的长线。

落位（`:4619-4680`）：

- 共享地（≥2 伙伴，且伙伴 y 差 ≤0.45、x 跨度 ≤6.0）：x 取全部伙伴地脚中点，y 取最低脚下方 0.5（`:4624-4636`）
- 单伙伴：按所接引脚旋转后的偏移方向三分支——
  - 脚在 origin 上方 → 地放上方 `y+0.5`、`angle=90`
  - 水平脚且是自由端（该节点除地外无其他 rf 引脚）→ 侧挂 `x ± 0.5`、`angle=0/180`
  - 其余 → 正下方 `y-0.5`、`angle=270`
- 端口伙伴额外横向错开 ±0.35（`:4641-4644`），避开端口符号边缘
- 无伙伴 → `(0.0,-0.5)`、270

地符号角度实测建档（`:4648-4651`）：0° 体在右、90° 体在上（倒置）、180° 向左、270° 体在下（正置）。

**这一套会被下一层重算**：`_gnd_normalized_angles`（`:5634-5667`，调用点 `:5891-5895`，auto 与 explicit 都走）按"地相对所接引脚的方位"重定角度，并剥 `mirror`：

```python
if abs(dy) >= abs(dx):
    out[gnd] = 90 if dy > 1e-9 else 270
else:
    out[gnd] = 0 if dx > 1e-9 else 180
```

无连线信息的默认 270（`:5665-5666`）。`tests/test_auto_layout.py:762-796` 固化了六个方位。

注意 `:5888-5890` 的注释写"下 0°/上 180°/右 90°/左 270°"，**与实现和测试都相反**（实际是下 270°、上 90°、右 0°、左 180°）。这是注释写错，不是代码写错。

### 2.8 注释件与端口朝向

注释件排位（`:4689-4707`），行高 `annot_y(n) = 1.6 + 0.62*(n-1)`：

- `VAR` → `(min_x, annot_y(max(参数行数, 变量数)+1))` 左上
- `MSUB` → `(min_x + 4.5, …)` 让开 VAR 文字块
- 其他（含仿真控制器）→ `(min_x, min_y - 3.2 - 2.2*k)` 左下，逐件下移 2.2

对称布局下 MSUB/VAR 有第二套定格（`:4715-4746`）。

端口朝向（`_normalize_port_angle`，`:2674-2681`，只在调用方没给 angle 时生效）：

- `TERM`：输入 0、输出 180
- `TERMG`：输入 180、输出 0

方向相反的原因（`:2658-2662`）：TermG 符号体在 origin 右侧、单脚在 origin 上，输入口不转到 180 的话第一段导线必然压符号。

标注避让最多 4 轮（`:4878`），候选偏移序列在 `:4971-4972`；全部候选被拒就"保持原位，由路由层处理"（`:4989`）。

### 2.9 失败与降级

布局层不抛错给用户，所有异常都在内部消化：

| 情形 | 行为 | 行号 |
|---|---|---|
| 端口间不通 | `_fallback_chain` 取最长简单链 | `:2985` |
| `adj_side` 全空 | 退回 `adj_all` | `:2985-2986` |
| 对称布局任一约束不满足 | 清空重来，走通用布局 | `:3215-3220` |
| 分支 BFS 找不到锚点 | 第二轮兜底 `(0.0, _row_y(1))` | `:4252-4258` |
| 行占位碰撞且 `row>=12` | 接受碰撞 | `:4313` |
| rail 摆位失败 | `raise` 后被 `except` 回滚 | `:3830-3865` |
| 标注避让 4 轮全败 | 保持原位 | `:4989` |

排查靠三个环境变量：`AUTO_LAYOUT_DEBUG`（`:4278`）、`SYM_ANNOT_DEBUG`（`:4893`）、`SYM_MATCH_DEBUG`（`:2995`）。这些都不进返回体。

## 3. 走线规则

### 3.1 规划（`plan_wire_routes`，`:5046-5414`）

对每条连接按代价递增尝试（`plan_one`，`:5162`）：

0. 共轴直连（也要过 `blocked()`）
1. 两个单拐点 L
2. 两个两拐点走廊：±1/±2/±3 格偏移、障碍 box 边 ±0.25
3. 全被拒 → 按 `_penalty` 罚分选最优：跨网引脚 +10/次、穿符号 +5 或 +2、跨网交叉 +8、长度 ×0.01

选中后按 `score(wp)` 排序，返回 `(共线扣分 -10/段, 曼哈顿长度)` 最小者（`:5210-5221`）。

规划失败不阻断：`build_schematic` 捕获异常，写 `layout_report["fallback_reason"]` 并降级为逐条在线寻路（`:5841-5849`）。

### 3.2 正交

主导方向规则（`:979-983`）：

```python
if abs(x2-x1) >= abs(y2-y1):  return [(x1,y1),(x1,y2),(x2,y2)]   # 横向为主：先竖后横
return [(x1,y1),(x2,y1),(x2,y2)]                                  # 纵向为主：先横后竖
```

斜段在五处被拦：`_route_clear`（`:1269-1270`）、`_wire_connection`（`:1448-1449`）、`connect_impl`（`:2096-2097`）、`wire_impl`（`:2117-2120`）、`_geometry_report`（`:1679-1683`）。

### 3.3 绘制

`_wire_connection`（`:1386-1454`）三条分支：

- `_bind_only` → 只 `_bind_pins`，不画线（`:1408-1412`）
- 有 `waypoints` → `_route_clear` 校验，不过则 `raise RuntimeError(f"指定折点使导线穿过元件或与已有导线交叉/重叠：{conn}")`（`:1433-1438`）
- 否则 `_route_around`（`:1440`）

`_route_around`（`:1294-1383`）四级兜底：直连 → 另一序 L → 网格 A*（Dijkstra，`margin=0.25`，拐弯罚 0.2，`:1360`）→ 网格细化（中点，约 0.125）→ `raise RuntimeError(f"无法找到不穿元件、不交叉的正交走线：{start} -> {end}")`。

`_wire_all_connections`（`:1457-1488`）：折点被拒的连接延后重试，仍失败才整体报错。

### 3.4 画线不等于连通

`_bind_pins`（`:934-983`）显式给 `pin.net` 赋值。docstring 原文记录 2026-09-24 实测：

> 几何重合不等于电气连通：`add_wire` 端点精确落在引脚上，网表里两个引脚仍在各自独立的 `N__x` 节点上。

合并已存在网络时，旧网络的其它引脚要一起迁移（`tests/test_build_gate.py:297-320` 固化）；接地网优先保留（`:945-946`）。

`wire_impl`（`:2136-2139`）**只 `add_wire` 不绑定**——手工 `wire()` 不改网表。`connect()` 才含绑定。

## 4. 门禁

三段时间点，行为完全不同。

### 4.1 写入期（不落盘）

| 门禁 | 判据 | 豁免 | 行号 |
|---|---|---|---|
| 坐标齐全 | explicit 模式下每个实例 x/y 必须齐 | 无 | `:5881-5886` |
| auto 只支持空图 | `n_before>0 and not recreate` | `recreate=True` | `:5952-5956` |
| 备份 | `recreate` 且备份失败则拒绝 | 无 | `:5928-5934` |
| 布局尺度 | 任一连接引脚距离 > **200 × 符号中位长边** | `allow_large_geometry` | `:2172-2202`、`:5986-5988` |
| 斜段 / 折点穿体 / 走线失败 | 见 3.3 | 无 | `:1448`、`:1437`、`:1482` |

尺度门禁的 `symbol_size` 是全部实例 bbox 长边的**中位数**（`:2186`），判据是相对比例不是绝对尺寸；无有效 bbox 时直接放行。

### 4.2 保存后只读复核（图已落盘）

关写句柄 → 只读重开 `d2` → 顺序跑（`:6016-6037`）：`_design_audit`、`_verify_params`、`_netlist_parameter_specs`、`_verify_var_values`、`_check_connection_list`、`_geometry_report`、`_annotation_issues`、`generate_netlist`。

汇总成 7 类 `problems`（`:6039-6075`），任一非空即抛（`:6117-6126`）：

1. 审计失败
2. 重开看不到这些实例（`missing`）
3. 实例数不符
4. 参数落盘不一致
5. 连线两端不在同一网络
6. 网表逐引脚等价失败
7. 导线几何复核失败

几何这一类（`_geometry_report`，`:1638-2063`）的 `problems` 包含：斜段、穿符号内部、无引脚 T 形搭接（`tap_no_pin`）、**异网**交叉或共线重叠、重复重合线段、同一节点两条平行同向线。`warnings`（同网交叉/重叠/T、网络归属不明、导线穿文字区）与 `unverified`（读不出折线顶点）**只进返回体，不阻断**。

网表门禁（`_netlist_gate`，`:5738-5777`）三种必拦：网表为空、核对过程抛异常、划分或参数有差异。docstring 口径是"没核过 ≠ 核过没问题"，三种都返回 `ok=None/False` 而不是静默通过。

### 4.3 仿真前（不在建图内）

`_gate_problems`（`:505-584`）7 类阻断：读不出实例、空设计、无控制器（含底层原文 `No Simulation Component specified`）、基板引用断裂、端口自短路、端口地脚无接地参考、需要端口的控制器却没有端口。

**建图时不拦**——只写进返回体 `sim_readiness.problems`（`:6111-6115`，注释"此刻不拦截，`run_simulation` 会再拦一次"）。真正阻断在 `run_simulation`（`:6757-6761`）。所以能建出一张"必然不能仿真"的图。

`_gate_warnings`（`:587-599`）只有 `floating_pins` 一类，前 12 条。

## 6. 提示词与代码的实际冲突

按影响排序。

**① auto 与"增量构建"互斥。** `backend/agent.py:372` 写"分多次 `build_schematic` 增量构建是安全的（追加模式）"，`:396` 写"完全不写坐标自动 auto"；两句合起来指向的操作被 `ads_ops.py:5952-5956` 直接拒绝。提示词与 schema 都没有"已有实例时 auto 会被拒"的提示。

**② 尺度规则缺 schema。** 见第 5 节。

**③ `allow_large_geometry` 两处口径相反。** schema 把开关交给模型（"确需超长导线时设 true"），提示词明确禁止使用。

**④ RLC 吸附零强制。** `E12/E24/E96/Coilcraft/Murata/IEC 60063` 在 `backend/` 下只出现在 `backend/agent.py:462-496`；`backend/design_service.py:617-627` 把优化候选连续值原样写回 VAR，无吸附、无档位校验、无复测门槛。这条纯靠模型自觉。

**⑤ 共享地被拆分未告知。** auto 模式下实例名和实例数量会变（`GND` → `GND_local2/3…`），提示词与 schema 仍在描述"共享同一 GND 符号的多元件按伙伴引脚就近挂置"这个 auto 模式下不存在的场景，也没说 netlist_equivalence 只核拓扑不报警号变化。

**⑥ "以实际引脚位置为准"只在复核期成立。** 规划期引脚来自静态档案 `_AUTO_PIN_OFFS`，不是读真实引脚。

**⑦ "文字绝不被导线穿过"是绝对化表述。** 实现只报告（`_annotation_issues` 明确"不拦截"，`:1594-1596`、`:6099-6102`），A-B 报告 `:180` 实测仍有 4 条文字区被穿过的警告。

**⑧ `mirror` 会被悄悄剥掉。** auto 模式剥 mirror（`:5818-5822`，理由 rotate-then-flip 会把引脚翻出规划位置），提示词与 schema 均未告知。

**⑨ `term_anchors` 是隐藏入参。** 它是 `build_schematic` 的有效参数（`:6004-6006`），但不在 schema 里，只由 `backend/device_library.py` 内部注入；它同时改变网表门禁的 `ignore_names`（`:6070-6071`）。

## 9. 结论（**历史记录**，整合后的结论见规则手册）

> 以下判断描述的是整合**前**的状态。整合已完成：规则集中到
> `schematic_rules.py`、判定原语统一、提示词与 schema 已挂上规则号。

现在这张图的生成规则是**可用但分层割裂**的：

- 布局、规划、绘制、复核是四套独立实现，"同一规则"实际上各有各的版本；`geometry_policy.py` 本该收敛这件事，但它没接线，所以收敛仍然停留在纸面。
- 强制力集中在"落盘后的复核"这一段（7 类 problems），而它的时序意味着违规定义已经写进磁盘；写入期只有尺度和走线两类硬拦。
- 提示词承载了大部分"应该如何"的知识（尺度、接地、吸附、SP1.SP），schema 只承载接口形状。谁只读 schema 就会漏掉一半规则，`allow_large_geometry` 更是两处口径相反。
- 仿真门禁故意后置到 `run_simulation`，代价是模型会先成功建出一张不能仿真的图，再被弹回来。

如果要动，优先顺序建议是先合 `geometry_policy.py` 与三套判定（这是所有"规划通过、复核不过"问题的总根），再补 schema 的尺度与 auto 边界说明（这两条直接导致模型走错路径），RLC 吸附与文字避让这类纯提示词纪律需要单独决定是否要落地成校验器。
