# ADS 2024–2027 × 功能 兼容性矩阵

> 口径（务必按此表述，不得夸大）：
> **ADS 2027 = 已实机验收基线；ADS 2024–2026 = 实验性适配（已完成官方文档
> 研究与离线验证，未实机验证）**。不存在"全面兼容 ADS 2024–2027"或
> "全部验收通过"的状态。
>
> 列说明：
> - **证据来源**：官方文档 / 实机核实 / 运行时能力检测（未知项如实标注）；
> - **实现状态**：适配层是否已实现该版本的路径；
> - **离线验证**：模拟接口契约测试（tests/test_capability.py 等，非实机）；
> - **实机状态**：是否在真实该版本 ADS 上执行过（2027 有，其余无）；
> - **默认**：未改配置时的开放状态；"实验性开启"指 config.ini
>   `[compat] experimental_<年份> = true`（开启**不代表**验证通过）。

## 图例

- ✅ 已支持（有证据 + 有实现 + 离线通过）
- 🧪 实验性（有实现 + 离线通过，无实机证据，需显式开启）
- 🔍 运行时判定（存在性由能力检测决定，文档无证据）
- ❌ 默认禁用 / 不支持
- ❓ 未知（文档缺失，运行时探测兜底）

规则汇总（与 `backend/adscompat.gating_decision` 一一对应）：
1. 能力检测不过 → 一律拒绝（`capability_missing`）；
2. 未知版本 → 读放行、写拒绝（`unknown_version`），`allow_unknown_version=true`
   可显式放行（不受支持）；
3. 已验证年份（2027）→ 全放行；
4. 实验性年份（2024–2026）→ 读放行；写/执行需对应年份 `experimental_<年份>=true`
   （`experimental_disabled`），开启后 reason 仍注明"未实机验证"。

## 五、已知限制

1. **ADS 2024–2026 全部功能未在实机执行过**。上表所有 🧪/❓/🔍 行项，
   在取得对应版本实机环境前，只能给出"文档与离线验证完成"的结论。
2. ADS 2024 的 Python 自动化为 Beta 且需 `ads -python` 启动参数（官方）；
   插件在该版本能否被加载属于未知项，失败表现为"菜单不出现"，不影响 ADS。
3. 线程契约：后台仿真（`sim_off_main_thread`）的官方依据仅覆盖 2025 U2.0+；
   2024 默认主线程执行（保守）。
4. 几何常量（Orientation/PointF）位置在不同构建可能漂移（2027 已有多路径
   尝试）；探测为 unknown 时自动布局与 Layout 审查自动禁用，**不会**返回
   "检查通过"。
5. 写失败语义：不确定失败前是否已写入时，适配层**不自动换接口重试**，
   一律报告失败并提示人工检查（复用 1.0.1 的保存后复核机制）。
6. 在线 Python API 参考（edadownload）未能访问；接口签名核对依赖
   `tools/real_machine_check.py`（未来取得实机后执行）。

## 六、ADS 2024–2026 实机验收清单（待环境可用时执行）

运行 `python tools/real_machine_check.py --ads-dir <目录>`（该脚本只读优先），
或按以下步骤手工验收：

1. 只读检查：面板出现 → 兼容性状态…（菜单）→ 确认版本识别来源与能力三态；
2. 只读工具逐个执行（get_workspace_info / list_designs / get_design_variables /
   check_connections / read_dataset）；
3. 打开测试工作区，写入类工具在**隔离的临时工作区**逐个验证
   （set_design_variables → 保存复核 → 撤销；build_schematic 在新建 cell；
    run_simulation 用最小 AC 控制器）；
4. run_python 冒烟（print 版本、枚举位置探测）；
5. 记录结果到 docs/验证记录-<版本>.md，并更新本矩阵的"实机状态"列。
