# 村田模型仿真启动失败修复记录

日期：2026-10-31（Asia/Shanghai）

## 结论

已修复插件仿真子进程环境丢失问题，并通过真实 ADS 2027 仿真验证。没有更改电路参数、拓扑或全局系统环境，也没有重新安装 ADS。

## 根因与分层诊断

1. 退出码 3221225781（0xC0000135）发生在 Windows 加载阶段，不能作为模型未定义的证据。
2. `addon/ads_agent/ads_ops.py` 中 `WorkspaceSimulator._execute` 覆盖了 SDK 的 `ADSEnvironment._execute`，旧实现错误假设父类会预先通过 `env` 传入完整环境。实际 SDK `run_netlist` 调用覆盖方法时只传 `extra_env`。原实现因此把少量模型路径变量作为完整子进程环境，遗漏 PATH、HPEESOF_DIR 等环境。
3. 修复从 SDK `self._env` 开始构造独立副本，再依次合并显式 env、extra_env 和本次工作区 ADSlibconfig 路径。保留 SDK 的 DLL 路径设置以及 Python/Qt 环境清理；没有 SDK 属性的测试替身才回退到 os.environ。
4. 现场当前设计已存在 `muRataLibWeb_C:muRataLibWeb_C_Include` 和 `muRataLibWeb_L:muRataLibWeb_L_Include`。历史 08:36:42 网表以及本次生成网表均包含两个包各自的 `circuit/models/encode.net`。因此用户引用的“无 include”记录已不是本次检查时的文件状态。
5. 本次递归网表检查确认 muRataLibWeb_C 与 muRataLibWeb_L 两个编码名称都已映射到当前工作区内对应 `.library`，两份 encode.net 文件检查通过。没有必要通过修改全局配置或补 DESIGNKIT 注册来绕过当前问题。
6. `NetlistInclude` 的 File 参数并不适用；此处已有原厂 Include，无需继续猜测 IncludePath 的复合类型赋值方式，也不应重复引入整包模型。
